## 1. 必须保留的主线

**核心问题：同样稀缺的类别数据，如何在多人持续修改同一个共享模型时，支撑已具备能力的保留？**

顺序固定为：现实视觉场景及两个分析维度 → FedAvg＋LoRA 的尾类轨迹暴露保持困难 → 固定边际分配对照说明客户端结构值得研究 → 客户端更新的功能贡献揭示正向支持与持续改写之间的关系 → 固定 LoRA A 是参照、继续适配有价值 → 主模块以功能反馈与有效来源协调更新 → 辅助模块在共享更新中利用外部客户端信息 → 以共享模型的尾类保持及完整分类表现检验。

这条顺序来自《故事线》p1–3 的问题/机制、p4–5 的模块角色、p5–7 的完整叙事。《日常讨论》p1–2 的两个轴和 p3 的划分控制保留；p4 的旧方法建议不再作为当前方法。

## 2. 两个轴的精确定义

设 N=(n_kc) 为 client×class 计数矩阵，n_c=Σ_k n_kc，n_k=Σ_c n_kc。

- 类频轴：n_c 或全局类比例 p(c)，即每个类别一共有多少训练图像。
- 客户端分布轴：p(k|c)=n_kc/n_c，即同一类别的图像分布在哪些客户端、各占多少。
- 可写恒等式 n_kc=n_c p(k|c)，简单清楚地显示“数量”和“归属分布”。
- 客户端容量 n_k 是行边际，**不等于**类别来源结构。旧 PDF p1 把 client-marginal 与 support topology 并列，正文宜改成“类别证据的客户端分布”。
- 两者是分析维度；不要把“正交轴”写成未经证明的统计独立或完全无耦合。

λ_T/α_T 是第二个轴内部的两个划分旋钮，不能称为论文的两个分析轴。

代码依据：utils/datasplit.py::partition_client_longtail（约505行）。固定全部输入样本及全局类计数：

1. 设 specialist 客户端比例 q_T（当前0.1），尾类总量 N_T。尾类进入 specialist 的总比例 q_T+(1-q_T)λ_T；λ_T=.75 时目标约 .775（整数预算取整）。
2. 非尾类进入 specialist 的预算 round(ρ N_T q_T(1−λ_T))；因此 λ 同时改变专门化和非尾类混入，不能解释成只改变一个支持者数量。
3. α_T 控制组内 Dirichlet 分配。**现代码同一个 intra_group_alpha 同时用于 specialist 和 general 两组**，并非仅 specialist。PDF p3 对下两幅图的解释偏窄。
4. 当前类角色：前80类/后20类；前27客户端/后3客户端。评估 Head20/Middle60/Tail20 的分组与上述划分 head80/tail20 不同；正文采用“非尾类80”描述前者。
5. λ/α 扫描保持 n_c，但一般不保持逐客户端 n_k。固定 n_k 必须用另一个 matched 对照。

## 3. 固定边际与普通 Dirichlet 的职责

utils/datasplit.py::partition_fixed_marginal_dirichlet（233行起）先生成类×客户端偏好，再按剩余容量分配，每样本一次，精确保留 n_k 与 n_c。

严格匹配对照可回答“在相同全局类样本数、相同客户端容量下，改变 client–class 分配后会怎样”。它同时改变支持集合、共现、局部数据组合，不能把结果唯一归因于 N_eff 或支持者数量。

普通 noniid-labeldir-fine 改变完整分配协议，不能套用“双边际固定”说明。λ/α 扫描、普通 Dirichlet、固定边际 matched 三者应在蓝图的实验任务表中分开。

## 5. 原 PDF 必须修正的节点

3. 《日常讨论》p4的可靠性门控、正交保护、shared/residual双路结构是旧候选方法；当前不采用，不能借用这些标题描述代码。

6. 当前 B反馈不限定3个protocol tail clients，也不只用尾类；因此“尾部客户端”“持尾类客户端”“tail20”必须分开。

## 6. 可采用的思维模板与定位

建议主定位：**以具体问题观察驱动的 Technique paper**；Client-LT提供可控分析设定，主方法为功能保持，B为共享校准辅助。若把“新问题设定”作为主创新，需更强新颖性综述与跨数据证据，不能只把两轴画出来算创新。

| 思维节点 | 可用论点 |
|---|---|
| 背景 | 联合视觉分类中少见类别可能只出现于少数采集源；所有人最终使用同一共享模型 |
| 局限1 | 单看类频和最终精度，不能区分没学好与后续没保持 |
| 局限2 | 相同类频下客户端分配会改变局部训练的功能贡献与保持表现 |
| 关键想法 | 用本地类别功能反馈和有效来源信息，协调继续适配与已有功能保持 |
| 挑战1 | 共享更新持续改变时，确定哪些已验证的类别功能需要保持、谁提供可靠支持 |
| 模块A | 当前与历史功能目标＋有效来源优先级＋分类项，共同修正允许继续变化的LoRA A |
| 挑战2 | 直接监督有限，外部客户端更新的帮助与损害混合，需要使共享组合服务于尾类 |
| 模块B | 以持尾类客户端反馈校准独立donor C的共享组合；效用由A/AB/校准对照判定 |
| 贡献1 | 从样本数量与客户端分布联合研究共享尾类保持；提供匹配分配与轨迹证据 |
| 贡献2 | 来源感知的功能保持方法，明确A承担主贡献 |
| 贡献3 | 完整分类/保持/控制实验检验收益与代价；B纳入辅助实现贡献，不单立强创新 |

四链自洽检查：局限→想法、想法→挑战、挑战→模块均可闭合；模块→贡献取决于B是否保持“共享组合校准”的实际定位。若坚持逐类筛选宣称，该链目前断裂。
