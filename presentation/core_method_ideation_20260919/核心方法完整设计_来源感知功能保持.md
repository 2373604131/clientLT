# 来源感知的功能保持适配：完整方法设计

日期：2026-09-19。

状态：可用于下一轮实现的完整协议设计；新超参数为预先指定的开发起点，尚未经实验验证。本轮不修改训练代码、不运行实验。

工作名称：Source-aware Functional Retention Adaptation，来源感知的功能保持适配。名称不代表首创性认证。

本设计以“维护来源”为主线，将“已学增益持续保持”融合进同一个 A 更新目标。没有未来 B 训练预测、分支接受/拒绝、历史模型恢复或动态冻结控制。

## 1. 方法目的与中心思想

在少数客户端持有稀缺类别数据的联合识别任务中，学习到有用知识与持续保留这种知识是两件不同的事。

已有 Client-LT 实验呈现了明确的学习—保持矛盾：开放 A 能提高适配收益，但充分训练时尾类后期保持较弱；限制 A 变化能够稳定训练，却限制进一步适配。我们针对这个矛盾设计方法，不把“A/B 天生具有某种知识分工”作为前提。

中心思想：

> 以具体功能的正向维护来源为依据，确定共享适配需要保留的贡献；再利用实际获得的功能参照，持续修正 A 更新中造成这些贡献流失的部分。

整个方法只有两个学术模块：

1. 来源感知的功能证据：测量各客户端更新对本地具体功能的作用，区分支持来源及其集中程度。
2. 持续功能保持的 A 合成：把本轮贡献目标和历史已学参照写进同一个目标，形成最终共享 A。

第二个模块使用第一个模块的功能、来源证据和尺度，不另建一套教师模型或独立记忆网络。

## 2. 训练结构与沿用配置

### 2.1 模型与参数

对每个注入 LoRA 的线性层：

\[
W_\ell=W_{0,\ell}+s_\ell B_\ell A_\ell.
\]

采用仓库当前 S 配置：

| 项目 | 设定 |
|---|---|
| 基础模型 | CLIP ViT-B/16 |
| LoRA 位置 | 视觉编码器最后 3 个 Transformer block 的 q、v 投影 |
| rank | 4 |
| alpha / dropout | 1 / 0 |
| 实际缩放 | 仓库使用 alpha/sqrt(rank)，此处为 0.5 |
| 冻结参数 | 原始骨干、文本侧与其余非 LoRA 参数 |
| 客户端 | 30 个，每轮全部参与 |
| 总轮数 | 100 |
| 正常训练 | 每轮 A 固定，B 本地训练 3 epochs |
| A 学习阶段 | 第 1–90 轮，每轮本地 A-only 训练 1 epoch，再进行功能保持合成 |
| 第 91–100 轮 | 继续原定的 B 训练，用于观察后续适应与保持 |
| 本地损失 | A 提案和 B 训练都用现有 LA-CE，tau=1 |
| 本地学习率 | A=0.001，B=0.001，沿用当前常数学习率设定 |
| 优化器 | 保留当前 S 的 SGD 设置；A 提案 momentum=0.9、weight decay=0 |
| B 聚合 | 按客户端样本量加权 |
| 数据划分 | Client-LT；外部验证使用标准 noniid-labeldir-fine，Dirichlet beta=0.5 |

缩放和训练节奏分别依据 [LoRA 实现](../../utils/loralib/layers.py)、[S runtime](../../utils/cliplora_la_control.py) 与 [启动配置](../../scripts/run_cliplora_a_refresh.py)。

A 在服务器保存唯一共享状态；客户端收到相同副本后提出更新。B 也保存一个共享聚合状态，不引入持久化的私有 B。服务器保存 A 并不意味着服务器持有训练图像。

### 2.2 一轮的共同参照

第 t 轮开始于共享模型 \((A_t,B_t)\)。

1. 各客户端固定 \(A_t\)，正常训练 B。
2. 服务器完成 B 聚合，得到 \(\bar B_t\)。
3. 本轮所有 A 证据和候选方向统一以
   \[
   M_t^0=(A_t,\bar B_t)
   \]
   为参照。

必须使用共同的 \(\bar B_t\)，不能让某客户端带着自己的本地 B 来评价 A，而另一客户端使用全局 B。

### 2.3 LA 的准确位置

\[
\mathcal L_{\mathrm{LA}}(x,y)
=-\log\frac{\exp(z_y+\tau\log\pi_y)}
{\sum_c\exp(z_c+\tau\log\pi_c)}.
\]

这里 \(\pi_c\) 沿用当前训练池的全局类别先验。LA 只用于本地 A/B 训练，不把它描述为服务器的聚合算法。新功能反馈用原始分类分数，不再叠加 LA，以免把损失校正值误当成模型已经具备的分类能力。

## 3. 功能单元与私有见证集

### 3.1 什么是功能

一个功能单元 \(q=(i,c)\) 指客户端 i 对本地类别 c 的一小组固定样本的分类能力。

它不是服务器上的全局类别标签，也不是某个 A 通道的语义命名。不同客户端的同类样本可以构成不同功能单元，因为它们的图像内容及本地经验不同。

客户端本地知道类别 c；服务器使用不包含类别编号的功能 token。服务器知道 token 属于哪个反馈客户端，但算法不需要知道它是否为 Tail。

### 3.2 见证样本协议

每个本地非空类别固定选择至多 8 张训练图像：

\[
|\mathcal W_q|=\min(8,n_{i,c}).
\]

选择只依赖固定种子与已有本地样本顺序，不按测试表现挑选。样本较少的类别全部使用，不删除单样本类别。

每张图像使用两个固定视图：

- 视图 1：现有确定性评估预处理；
- 视图 2：同一确定性图像的水平翻转。

这两个视图与参数初始化和训练随机数流独立，不额外采样随机增强。

本设计明确采用训练端见证集：这些图像继续参加原有本地训练，不改变 Client-LT 的数据容量与训练预算。因此，方法信号是 training-set functional evidence，不称为独立验证集上的真实知识。固定双视图与连续多轮确认用于降低偶然拟合影响，但不构成泛化保证。

已有来自 LT 训练池之外的 ERI/factor_roles 诊断 probe、官方测试集均不用于本方法计算、参照登记或超参数选择。这保持与既有 S 的训练数据一致，也避免给算法额外补充尾类图像。

### 3.3 功能量：未缩放的分类裕度

设 \(\operatorname{cos}_c(M,x)\) 为模型对类别 c 的图文余弦相似度。定义：

\[
m(M,x,y)=
\operatorname{cos}_{y}(M,x)
-\max_{c\ne y}\operatorname{cos}_{c}(M,x).
\]

\[
F_{q,v}(M)=
\frac1{|\mathcal W_q|}
\sum_{(x,y)\in\mathcal W_q}m(M,T_v(x),y).
\]

该量使用 logits 除以固定的 CLIP logit scale 后计算，不含 LA 调整。

大白话：正确类别比最强错误类别领先多少。它比少量样本上的离散 accuracy 更适合观察小更新。

它是组平均裕度，不意味着组内每张图像都分类正确。两视图分别保留，不先平均掉其中一个视图上的损害。

## 4. 模块一：来源感知的功能证据

### 4.1 客户端提出 A 更新

各客户端从同一 \(M_t^0\) 出发，固定 \(\bar B_t\)，用正常 LA-CE 训练 A 一个本地 epoch：

\[
d_k=\operatorname{vec}(A_{t,k}-A_t).
\]

只上传 A 更新，不上传本地 B、图像或本地类别编号。

服务器计算学习提案中心：

\[
d_0=\sum_{k=1}^{K}p_kd_k,\qquad
p_k=\frac{n_k}{\sum_jn_j},
\]

以及本轮提案尺度：

\[
R_t=\sqrt{\sum_kp_k\|d_k\|_2^2}.
\]

提案中心表达普通训练想往哪里学习；\(R_t\) 表达本轮客户端实际提出的更新尺度。最终 A 由第 6 节的统一功能保持目标形成。

### 4.2 精确的小坐标系：用于反馈，不是新模型

把所有 A 提案排成矩阵：

\[
D=[d_1,\ldots,d_K]=UC.
\]

使用 reduced QR 构造正交列矩阵 U。当前参数维度远大于 K，U 的列数至多为 K=30；C 的每列对应一个客户端提案的坐标。

服务器向客户端发送 U 和 \(R_t\)，C 留在服务器。

客户端计算本地功能梯度：

\[
g_{q,v}=\nabla_A F_{q,v}(M_t^0),
\]

然后只上传：

\[
z_{q,v}=U^\top g_{q,v},\qquad
\sigma_{q,v}=R_t\|g_{q,v}\|_2+\epsilon,
\]

以及当前功能分数、历史参照等标量。

服务器由

\[
g_{q,v}^{\top}d_k=z_{q,v}^{\top}C_{:,k}
\]

得到所需响应。这是更新张成空间内的精确内积表示，不是随机投影近似，不改变 LoRA rank，也不限制最终修正方向只能处于 U 中。

需要区分：坐标内积是精确的；用梯度内积预测有限 A 更新的功能变化仍是一阶近似。后续修正使用真实模型的功能损失。

### 4.3 正向支持与支持集中程度

定义一个客户端对功能 q 的双视图支持：

\[
r_{qk}=\min_{v\in\{1,2\}}z_{q,v}^{\top}C_{:,k},\qquad
a_{qk}=[r_{qk}]_+.
\]

两个视图都预测受益时，才计入正向支持。

计算：

\[
P_q=\sum_ka_{qk},\qquad
N_q^{+}=\sum_k\mathbf1[a_{qk}>0].
\]

有效支持来源数：

\[
N_q^{\mathrm{eff}}=
\frac{(\sum_ka_{qk})^2}{\sum_ka_{qk}^2},
\]

当没有正向支持时定义为 0。

来源稀缺权重：

\[
s_q=\frac1{\max(1,N_q^{\mathrm{eff}})}.
\]

这里既记录正向来源的个数，也记录支持强度是否集中。例如，十个来源中九个几乎没有作用，不应被当成十个同等有效的维护者。

支持使用原始 A 提案的作用，不先乘样本聚合权重 \(p_k\)。这样，功能来源证据不会在测量之前就被普通聚合权重再次压低。

### 4.4 当前贡献目标保留绝对幅度

定义平均正向贡献尺度：

\[
u_q=\frac{P_q}{\max(1,N_q^{+})}.
\]

若存在正向支持，本轮的功能目标为：

\[
T_{q,v}^{\mathrm{current}}
=F_{q,v}(M_t^0)+\rho u_q,\qquad \rho=0.5.
\]

意思是：对于客户端提出的正向功能改善，要求共享更新努力保留其中一部分。

\(s_q\) 决定维护来源是否稀缺；\(u_q\) 决定本轮正向改善有多大。两者分开，不能只留下归一化后的相对权重而抹掉实际改善幅度。

该目标是优化意图，不是承诺所有功能都能同时达到。不同功能之间可能冲突，由统一优化协调。

## 5. 融合机制：确认并登记已学功能

### 5.1 只记录实际提交模型，不记录候选预测

在训练开始前记录每个功能的初始水平：

\[
F_q^{\mathrm{init}}
=\min_vF_{q,v}(M_{\mathrm{init}}).
\]

每个正式轮次结束后，客户端对实际提交模型 \(M_t\) 测量：

\[
E_{q,t}=\min_vF_{q,v}(M_t).
\]

每 5 个正式轮次形成一个固定块：

\[
C_{q,b}=\min_{t\in\text{block }b} E_{q,t}.
\]

只有当

\[
C_{q,b}\ge\max(0,F_q^{\mathrm{init}})+\delta_{\mathrm{reg}},
\qquad\delta_{\mathrm{reg}}=0.001,
\]

才登记该功能已获得稳定的正向分类改善，并记录参照 \(H_q=C_{q,b}\)。之后满足同样条件、且连续块水平更高时，更新 \(H_q\)。

这不是按测试集寻找最佳轮次，也不取单轮尖峰：登记值是连续 5 轮、两个视图都实际达到的组平均水平。不能把它表述为统计置信下界。

客户端仅需保存初始标量、已登记标量、登记标志和当前块的最小值。无需保存一份历史 CLIP，也无需维护欠账队列。

### 5.2 当前贡献与已学保持进入同一个目标

对每个功能、每个视图，目标由可用证据形成：

- 有本轮正向支持：使用当前贡献目标；
- 已登记历史能力：使用历史功能参照；
- 两者都有：取二者较高者。

即：

\[
T_{q,v}=
\max\{\text{有效的 }T_{q,v}^{\mathrm{current}},\
\text{已登记的 }H_q\}.
\]

这一步把方向②和③真正融合起来：它们不是两个独立的损失插件，而是共同定义同一项功能应该努力保持到什么水平。

一个关键情形：某项能力过去已确认学会，本轮却没有任何正向维护来源。它仍保留历史目标，且 \(N_q^{\mathrm{eff}}=0\) 对应最高的来源稀缺权重。不能因为本轮缺少新改善，就把已有能力从保持目标中删除。

未形成当前贡献目标、也未登记历史参照的功能，本轮不产生保持目标。算法不把所有高损失样本都视为已学知识。

### 5.3 权重的公开定义

令 \(\mathcal Q_t\) 为本轮有功能目标的单元，采用：

\[
\omega_q=\frac{s_q}{\sum_{j\in\mathcal Q_t}s_j}.
\]

数值实现中的分母使用固定 \(\epsilon\)，空集合的损失按空和处理。

功能单元在来源加权前具有相同基准权重。这是显式的功能级目标设计，不是声称维持了原来的样本加权目标；A 提案中心和 B 聚合仍保留样本权重。

必须在消融中使用完全相同的功能单元和基准权重，单独取消来源差异，才能判断来源机制是否有独立贡献。不能把功能粒度本身带来的均衡效果都归给来源稀缺性。

## 6. 模块二：持续功能保持的 A 合成

### 6.1 一个统一的优化目标

记 \(\theta_t=\operatorname{vec}(A_t)\)，提案中心为：

\[
\bar\theta_t=\theta_t+d_0.
\]

服务器寻找修正向量 e：

\[
\begin{aligned}
\min_e\quad&
\frac{\|e\|_2^2}{2(R_t^2+\epsilon)}
+\frac{\lambda_F}{2}
\sum_{q\in\mathcal Q_t}\omega_q
\frac12\sum_{v=1}^{2}
\left[
\frac{T_{q,v}
-F_{q,v}(\bar\theta_t+e,\bar B_t)}
{\sigma_{q,v}}
\right]_+^2\\
\text{subject to}\quad&
\|e\|_2\le\kappa R_t.
\end{aligned}
\]

预设 \(\lambda_F=10,\ \kappa=1\)。

三个部分各有明确作用：

- 第一项要求尽量保留正常本地训练提出的学习方向；
- 第二项只惩罚未达到目标的功能，不惩罚功能继续变好；
- 修正范围把额外 A 改动限制在本轮提案的实际尺度内。

\(\sigma_{q,v}\) 将功能误差换算到可比较的更新尺度，避免某些功能只因梯度整体较大就支配目标。它在本轮证据阶段确定，并在本轮所有修正步保持固定。

最终提交：

\[
A_{t+1}=\operatorname{unvec}(\bar\theta_t+e^{(J)}),
\qquad B_{t+1}=\bar B_t.
\]

不要求 A 满足某个机械的最小位移，也不宣称每个样本绝不下降。方法目标是改善学习与保持的共同结果，实际位移、目标满足程度和功能变化都需要记录。

### 6.2 分布式求解，不上传每项完整功能梯度

服务器没有图像，因此真实功能损失在各客户端计算。

每个客户端 i 接收候选 A、自己的功能目标与权重，计算：

\[
\mathcal L_i^{\mathrm{func}}
=\frac12
\sum_{q\in\mathcal Q_t\cap i}\omega_q
\frac12\sum_{v=1}^{2}
\left[
\frac{T_{q,v}-F_{q,v}}{\sigma_{q,v}}
\right]_+^2.
\]

客户端仅上传一个合并梯度：

\[
G_i=\nabla_A\mathcal L_i^{\mathrm{func}}.
\]

服务器对它们求和：

\[
G=\sum_iG_i.
\]

这里不能再次乘客户端样本权重。功能权重已经进入本地损失，再乘一次样本量会改变所定义的目标。

### 6.3 固定三步修正

设置 \(e^{(0)}=0\)，固定 \(J=3\) 次通信修正步。每一步重新在当前候选 A 上计算真实功能梯度：

\[
e^{(j+1)}
=\Pi_{\|e\|\le\kappa R_t}
\left(
e^{(j)}
-\eta_F\left[
e^{(j)}
+\lambda_F(R_t^2+\epsilon)\sum_iG_i^{(j)}
\right]
\right),
\]

\[
\eta_F=\frac1{1+\lambda_F}.
\]

这是归一化尺度下的固定步数投影梯度求解。它不宣称三步达到非线性目标的全局最优；J 和步长是预先固定的求解配置，不根据测试表现决定运行几步。

每一步所有客户端都从同一个候选 A 计算梯度，客户端内部只累积梯度，不自行做多步更新。服务器完成一次合并更新后才进入下一步。

最后一轮修正后的候选就是本轮提交模型。梯度修正中的投影仅约束修正幅度，不选择另一个模型分支。

### 6.4 为什么不是整体奖励某个客户端

同一客户端对功能甲可能有帮助，对功能乙可能有害。来源响应逐功能计算，保持梯度也逐功能加权后再合并。

最终修正方向来自真实功能梯度，允许包含原始客户端提案集合之外的方向。U 只压缩来源响应，不把最终模型限制为一组客户端标量权重的组合。

因此方法直接操作的是共享 A 对功能的作用，而不是给整个客户端统一贴上“重要”或“不重要”的标签。

## 7. 一轮完整通信与计算流程

| 阶段 | 客户端操作 | 上传内容 | 服务器操作 |
|---|---|---|---|
| 正常 B 训练 | 共同 A 下用 LA 训练 B 3 epochs | B 参数或更新 | 原有样本加权 B 聚合 |
| A 学习提案 | 共同 A、共同 B 下用 LA 训练 A 1 epoch | A 更新 \(d_k\) | 形成 \(d_0,R_t,U,C\) |
| 功能证据 | 在共同 \(M_t^0\) 上计算双视图功能梯度 | token、F、\(U^\top g\)、梯度尺度、历史参照 | 计算支持来源、绝对改善尺度与功能目标 |
| A 修正，第 1–3 步 | 在同一候选模型上累积本地功能梯度 | 每客户端一个合并 A 梯度与损失标量 | 求和并更新共享 A |
| 正式提交与登记 | 在提交模型上记录双视图功能 | 必要的标量统计 | 提交唯一模型；不使用官方测试决定提交 |
| 下一轮 | 正常训练 B | 按原流程 | 继续训练 |

正式测试只读取已经提交的模型，测试结果不进入以上计算。

第 91–100 轮按 S 的既定节奏继续 B 训练，并持续记录功能与测试表现，不产生新的 A 提案。

## 8. 伪代码

## 9. 隐私边界与开销

### 9.1 服务器可见和不可见的内容

服务器可见：

- 与现有聚合一致的客户端总样本权重和 A/B 更新；
- 功能 token 所属客户端、功能响应坐标、分数与历史参照；
- 每次修正中合并后的功能梯度。

本模块不上传：

- 原始图像、逐样本标签、文本类别名称；
- 功能 token 对应的全局类别编号或 Tail 身份；
- 每项功能的逐类样本数；
- 全部逐功能高维梯度。

但 token 数量、长期响应和梯度仍可能泄露分布信息；U 也公开了集体更新子空间。这是数据不集中条件下的研究协议，不附加 DP、安全聚合或不可推断的隐私保证。现有 LA 的全局先验访问权限单独沿用，不把整个系统称为完全不访问类别统计。

### 9.2 通信成本必须单列

记 A 参数维度为 \(P_A\)，功能单元数为 Q，坐标数 \(r_U\le30\)。

主要新增通信是：

- 向各客户端下发 U：每客户端 \(P_A r_U\) 个数；
- 上传功能证据：大约 \(2Q r_U\) 个坐标及 \(O(Q)\) 个标量；
- J 次修正：每次每客户端上传 \(P_A\) 维梯度，并接收候选 A。

逐客户端单播口径下，下发 U 的总量是 \(K P_A r_U\)，不是只算一份 U。QR 不需要把 C 下发给客户端。

与上传全部逐功能梯度相比，小坐标系显著缩小反馈包；相较原 S，它仍增加通信与反向计算。不得把总成本写成与 S 完全相同。

### 9.3 计算和存储

- 证据阶段：每项功能的双视图梯度；
- 修正阶段：每次对各客户端固定见证集做一次功能损失梯度累积；
- 历史登记：提交模型的双视图前向；
- 服务器：小列数 QR、响应矩阵及梯度求和。

客户端可逐功能处理并释放计算图，服务器不保存所有功能的高维梯度。固定视图、固定骨干部分和固定文本特征可作实现缓存，但不将缓存包装为方法模块。

沿用单 GPU 串行模拟即可实现协议；实际时间取决于功能数量和数据读取，不在设计阶段虚构训练时长。

## 10. 预先指定的开发参数

| 参数 | 初始值 | 含义 |
|---|---:|---|
| witness_per_local_class | 8 | 每项本地功能至多 8 张见证图像 |
| fixed_views | 2 | 原图确定性视图、水平翻转 |
| current_gain_fraction，\(\rho\) | 0.5 | 本轮希望保留的平均正向贡献比例 |
| history_block_rounds | 5 | 连续功能水平确认窗口 |
| history_registration_margin | 0.001 | 相对初始/正裕度的登记改善门槛 |
| retention_weight，\(\lambda_F\) | 10 | 功能保持相对于提案中心的强度 |
| correction_steps，J | 3 | 每个 A 学习轮次的固定修正步数 |
| correction_radius，\(\kappa\) | 1 | 修正半径相对于本轮提案 RMS 范数 |
| correction_step_size | \(1/(1+\lambda_F)\) | 与主强度绑定，不再增加自由学习率 |
| numerical_epsilon | \(10^{-8}\) | 仅用于尺度和空和等数值定义 |

这些不是最优参数声明。第一版固定使用，不开展所有参数的组合搜索。优先检查功能信号是否有用，再决定是否有必要调整 \(\lambda_F\) 和 \(\rho\)。

本表的 \(\lambda_F\) 与 Client-LT 划分的 specialization_lambda=0.75、LA 的 tau=1、标准 Dirichlet 的 beta=0.5 是不同参数。

## 11. 必须同步记录的证据

### 11.1 结果指标

沿用 Overall、Head20、Middle60、Tail、Non-tail；主汇总使用最后 20 轮平均，同时记录峰值、峰值轮次、峰值到末轮/末 20 轮的下降。

曲线必须覆盖学习过程，不能只展示单个最优轮次。

### 11.2 功能与来源指标

每个功能、每个 A 学习轮次记录：

- 双视图当前分数、初始化分数、已登记参照；
- 正向来源个数、有效来源数、来源稀缺权重；
- 正向支持总量、平均正向贡献尺度；
- 当前目标、历史目标、最终目标；
- 提案中心的实际功能变化、最终 A 的实际功能变化；
- 目标缺口、三次修正的损失变化；
- 当前无正向支持但已登记历史能力的功能数量及其变化。

两种量分开：

- 本地提案提供的正向作用在共享模型里实现了多少；
- 共享模型过去已具有的能力在后续轮次还剩多少。

线性响应和真实功能变化也分开保存。可以用客户端自己提出的 A 更新，在自己的见证集上顺带检查近似方向是否一致；这个诊断不改变目标、提交或训练预算。

### 11.3 A 真的如何改变

记录：

- \(\|d_0\|\)、\(\|e\|\)、\(\|d_0+e\|\)、RMS 提案尺度；
- 修正前后方向夹角；
- 实际有效层更新 \(\sum_\ell\|s_\ell\bar B_\ell\Delta A_\ell\|_F^2\)；
- A 路径长度与子空间变化；
- 与普通 S 相同的 A 学习次数；
- 新增功能反向计算、修正通信、耗时与字节数。

这些观测用于确认方法的实际作用，而不预先把任何位移大小包装成成功。

## 12. 最小实验及闭环

### 12.1 第一批方法实验

| 组别 | A 提案及 B 训练 | 来源证据 | 历史已学参照 |
|---|---|---|---|
| S | 当前配置 | 原流程 | 无新参照 |
| S + 来源感知功能目标 | 相同 | 使用 | 不使用历史目标 |
| 完整方法 | 相同 | 使用 | 使用 |

已有同协议 S 可作为参考，不为检查哈希或重复确认问题另开训练。

快速方法 pilot 可以从共同 S 第 20 轮检查点继续训练。固定见证集后，用原始初始化模型与 S 第 16–20 轮的实际提交模型做前向计算，按同一登记规则建立初始历史参照；不重新训练这些轮次。需要服务器上的完整状态，轻量结果包不包含这些模型。

各新分支从相同第 20 轮状态开始，保持原定训练随机数流；只有完整方法在目标中使用历史参照。该 pilot 的结论限于后续学习与保持，完整训练结果另行报告。

### 12.2 首批有效后补的直接替换

1. 同样的功能目标、历史参照、修正步数与基准权重，取消来源差异：检验来源选择本身。
2. 同预算的普通功能梯度/正则化修正：检验新来源与参照是否优于一般额外优化。
3. 缩小 A 学习率或匹配有效 A 改动幅度的控制：检验学习—保持改善是否依赖方向选择。

先做能判定方法价值的最小组，不把全部替换扩展成方法开发前的前置任务。Tail-only 诊断标签只在离线分析中使用。

### 12.3 三个闭环问题

结果闭环：能否在保持充分适配收益的同时减少尾类后期下降？

来源闭环：维护来源集中的功能是否在普通 A 聚合后受到更大损害，方法是否针对这些功能产生了实际修复？

时间闭环：完整方法相较仅保护当前贡献，能否更好地保留此前已登记的能力，尤其是本轮没有新正向支持的能力？

同时检查标准 Dirichlet 是否保持正常性能。目标不是人为制造 Client-LT 高于 Dirichlet，而是解决 Client-LT 的实际损失并证明方法适用边界。

## 13. 仓库实现接口与容易混淆的事项

后续实现建议另建独立 runtime，不把新方法混入 E5 控制器。以下是计划接口，不是当前已存在的命令或文件：

- 功能见证集与登记器：构造固定本地样本、双视图、计算裕度、维护块统计。
- 来源反馈：构造 QR 坐标、计算投影反馈、形成来源统计与目标。
- A 合成器：发送候选 A、累积功能梯度、执行固定三步更新。
- 日志模块：分开记录普通训练、功能计算、通信和正式测试。

现有可复用部分：

- S 的正常 B 训练与 A-only 提案；
- LoRA 参数选择、共同状态恢复和现有数据划分；
- 未缩放余弦裕度的计算定义；
- 已有逐类评估与阶段日志。

实现约束：

1. 不能直接复用包着 no_grad 的 observational_model 来计算功能梯度。评分与梯度计算必须使用不同上下文。
2. 计算梯度时仅 A 可训练；B 和其他参数固定，但计算图必须能从分类输出传回 A。
3. 当前 LinearLoRA 使用显式加法分支，在 eval 模式仍可求 A 梯度；不得改成不可微的权重合并路径。
4. 每次客户端提案、每次服务器修正步，客户端都必须从对应共同状态开始。
5. 功能计算不得消耗正常训练的随机数流或修改其优化器状态。
6. 当前 A 提案的 SGD 状态不能混入服务器修正；服务器修正使用本文件定义的独立固定步数更新。
7. 功能梯度已经含 \(\omega_q\)，服务器直接求和，不再次按客户端样本量加权。
8. 新方法不读取控制器的全局 Tail 列表来决定保护谁。

## 14. 论文逻辑骨架与创新边界

论文类型：Technique Paper。

| 环节 | 内容 |
|---|---|
| 研究背景 | 稀缺类别集中到少数机构时，联合识别既需要适配，也需要保持 |
| 局限一 | 样本权重或整体贡献评分没有直接表示具体功能的正向维护来源 |
| 局限二 | 当轮聚合结果或一般历史对齐没有同时区分“当前贡献”与“已学能力”的保持需求 |
| 核心思想 | 用来源证据与实际获得的功能水平共同约束共享 A 适配 |
| 挑战一 | 不集中图像，仍需测量跨客户端更新对本地功能的作用 |
| 模块一 | 小坐标反馈下的来源感知功能证据 |
| 挑战二 | 当前学习和历史保持可能冲突，且服务器不持有功能样本 |
| 模块二 | 统一功能目标下的分布式 A 修正 |
| 计划贡献一 | 来源感知的功能保持适配框架，方法节 |
| 计划贡献二 | 精确来源响应接口与当前/历史目标的统一 A 合成，方法细节节 |
| 计划贡献三 | 学习—保持结果与来源、时间机制验证，实验节 |

设计层面四项逻辑对应成立；实验贡献仍是待完成目标，不写成已有发现。QR 是标准线性代数操作，不作为独立首创模块；投影梯度是求解工具，也不作为独立首创依据。

近邻界限：

- ShapFed 已研究类别相关贡献与聚合权重。我们的候选差异是功能维护来源及方向级修正，不能只改客户端分数的名称。[ShapFed 原文](https://www.ijcai.org/proceedings/2024/0554.pdf)
- FedProj 已使用知识记忆与梯度约束。我们的参照限于来源证据关联的实际已学功能，不以“使用记忆/投影”本身作为贡献。[FedProj 原文](https://arxiv.org/html/2505.20485v1)
- FedPuReL 已用零样本信号修正微调梯度。我们研究当前功能贡献进入共享模型及其持续保持，而非主要复刻零样本输出。[FedPuReL 原文](https://arxiv.org/html/2605.02247v1)

这三点限定方法应交付的实质区别，不保证最终性能，也不宣称全领域没有相似组合。

## 15. 可以用于汇报的方法描述

> 我们将 Client-LT 中的尾类保持问题表述为有效功能贡献的持续维护问题。客户端通过私有功能见证，提供各候选 A 更新对本地分类能力的响应；服务器据此识别维护来源集中的功能，并将其当前正向贡献与已经确认的学习成果统一为保持目标。随后，客户端提供功能梯度，服务器在保留正常适配方向的同时修正 A，形成可继续学习、又更关注稀缺功能保持的共享适配过程。

本轮 tech-paper-template 对设计的实际影响：将原来的两个研究方向落实为两个前后依赖的模块，并明确目标、计算接口、贡献与验证的对应关系。没有为补齐模块数量加入新的训练组件。
