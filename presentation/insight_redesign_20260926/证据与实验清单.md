## 4. 结构检查

论文定位为问题驱动的方法论文。核心设计句为：依据功能响应组织当前改善目标，并结合过去持续达到的功能水平，在共享适配中维护类别能力。

| 逻辑单元 | 本次设计 |
|---|---|
| 背景 | CAPT/FedPuReL 已呈现长尾适配中的能力失衡；本工作进一步检查相同全局数据下的分配与保持 |
| 局限 1 | 全局数量和整体精度无法完整描述当前两种分配下的尾类保持 |
| 局限 2 | 标签持有及本轮训练目标分别缺少更新功能作用与历史水平的信息 |
| 关键想法 | 将当前功能支持与实际达到的历史水平共同用于共享适配 |
| 挑战 1 | 从共同状态比较各客户端对同一功能的作用，区分一阶估计和实际变化 |
| 挑战 2 | 当前目标与历史水平可能冲突，需要在保持正常适配的同时协调，且不保证所有目标同时可达 |
| 方法模块 1 | 功能响应和来源证据；集中度优先级为需验证的优化规则 |
| 方法模块 2 | 统一当前/历史目标下的共享 A 修正；CP 为配套软约束 |
| 贡献落点 1 | 客户端分配与尾类保持的受限实证刻画 |
| 贡献落点 2 | 功能支持和持续参照结合的已实现方法 |
| 贡献落点 3 | 有明确版本、取舍和成本的验证；稳定性与关键归因仍需确认 |

局限—思路、思路—挑战、挑战—方法在设计上对应。方法—效果主张只能按当前开发证据表述，不能标成所有实证检查已完成。B 尚不需要被加入主贡献来满足模块数量。

## 5. 已做的核验

来源诊断核对了 1516 个 token 与真实训练清单、全部 90 轮数组和正向门槛；保存的 supported 与 positive_sources 均逐项吻合，重算有效来源数符合 float32 精度。新图从 CSV 或 NPZ 重算指标，不手工合成趋势。每张图附独立 caption 和可复现脚本。

来源诊断中的零支持状态、无支持类别和按单位/按类别平均均有计数；同一功能跨轮、不同功能或不同类别均不当作独立训练种子。已有单种子数据未绘制种子置信区间。

独立叙事复核要求补入非标签持有者候选人数参照，并将 Full/Flat 执行路径差异前移到首次解释处。本设计已落实这些边界。三张图是重新设计候选，不声明投稿版排版和全部机制验证已完成。
