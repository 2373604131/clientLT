# 功能保护式 A 更新与聚合：方法候选与闭环实验协议

日期：2026-09-19。状态：**设计稿，训练入口尚未实现，尚无新方法结果**。

本协议回答“下一步具体怎么做”，不要求先证明 A/B 硬分工，不增加已完成基线的重复完整训练，不开展哈希审计或冒烟测试。先用一套明确候选方法检验核心假设，失败则按机制数据修正，不通过不断调 epoch 寻找预期图形。

## 1. 要检验的主张

> 在 Client-LT 中，保护客户端本地可获得、但共享模型未充分保留的功能，可以改善持续 A 适配的尾类保持，并保留比永久冻结 A 更充分的学习收益。

三个层次不能混写：

1. **已有现象：**固定 A 稳定；持续开放 A 可提高适配，但 Client-LT 尾类代价较大；LA 不足以在所有训练策略中保证保持。
2. **机制假设：**稀缺客户端有益功能在聚合或后续更新中保留不足。可能是正贡献减少，也可能是负贡献增加，尚未排他确定。
3. **方法目标：**修改 A 聚合的实际方向，使学习继续进行而功能损伤减少。

不再把“A 主导客户端知识、B 主导类别知识”作为前提，也不要求 Client-LT 的绝对分数一定超过普通 Dirichlet。要缩小的是额外保持损失，不能通过压低 Dirichlet 制造差距缩小。

## 2. 首版只改哪里

底座采用已有 **S 密集交替**，而不是 J：B 阶段与 A 阶段分开，便于区分各阶段的损伤；不会把同时本地训练两个因子的配对误差混入主要干预。

不改以下配置：

| 项目 | 固定设置 |
|---|---|
| 数据 | 原有10847张长尾训练池；Tail20共153张；原客户端清单与类先验 |
| 划分 | Client-LT；随后普通 `noniid-labeldir-fine, beta=0.5` |
| 客户端 | 30/30全参与，B聚合仍按样本量 |
| 模型 | 视觉CLIP、top3 Q/V、rank4、alpha1、实际scale0.5、FP32 |
| 日常 B | 3 local epochs，SGD lr0.001、momentum0.9、wd0.0005 |
| 额外 A | 每次1 local epoch，SGD lr0.001、momentum0.9、wd0 |
| 损失 | B、A都使用原LA，tau=1；推理/功能评价不加LA |
| A时机 | 沿用S，第1–90轮；本次续训实际发生在21–90轮 |
| 末期 | 第91–100轮仅B；让新A有后续B适配，禁止第100轮再刷新A |
| 优化器 | 每客户端每阶段重置，与原协议一致 |

首版不同时加入新 LA 系数、私有 B、多 rank、动态门控、历史最佳回退、额外训练 epoch 或服务器按 Tail 标签调权。**本地 A 仍由 LA 训练；唯一主要算法改变是服务器提交的 A 更新。**

## 3. 一个具体、可实现的候选算法

暂称“功能保护式 A 聚合”（仅工作名，不宣称命名或算法的新颖性已完成文献验证）。核心是：普通聚合负责学习方向；客户端提供不希望被损伤的功能方向；服务器做最小必要修正。

### 3.1 一轮内的顺序

1. 从本轮全局模型 `M_pre=(A_t,B_t)` 开始，完成原有本地 B 三个 epoch。
2. 保存各客户端本地 B 状态 `M_k^B=(A_t,B_k)`，按原样本量权重聚合为 `M_bar=(A_t,B_bar)`。
3. 客户端比较自己的 `M_k^B` 与 `M_bar`，形成需要保护的功能方向。服务器不用知道类别名称或 Tail 列表。
4. 所有客户端从共同 `M_bar` 出发，只训练 A 一个 epoch，使用原 LA，上传 `delta_A_k`。
5. 服务器形成普通候选 `d0=sum(q_k*delta_A_k)`，再根据保护方向生成 `dP`。
6. 提交 `A_t+dP`，B保持 `B_bar`。下一轮按原S协议继续。

第3步的反馈计算不改变训练参数、优化器或训练随机流。各分支轨迹分离后，从各自当前模型重新计算反馈与本地更新，不复用旧S的梯度或把R的更新套到P上。

### 3.2 客户端用什么数据形成信号

首版复用每个客户端全部训练图片的固定评价视图，不改变既有训练池，不从仅39–46张样本的小客户端再次切掉训练数据。它应准确称为 **training-set functional gap proxy（训练集功能缺口代理）**，不是独立泛化测量。

每类功能分数采用原始logits上的真实类log-odds：

`F_kc(M) = mean_{x in local class c}[z_y - logsumexp(z_not_y)]`。

定义当前B聚合后的正缺口：

`g_kc = max(F_kc(M_k^B) - F_kc(M_bar), 0)`。

用本地类别频率 `pi_kc=n_kc/n_k` 保留原样本频率结构，并计算：

`w_kc = pi_kc*g_kc / sum_c(pi_kc*g_kc)`。

若总缺口为零，该客户端本轮不提供保护约束，但它的正常A更新仍照常参与FedAvg。数值归一化只使用固定机器容差，不引入按测试效果选择的门限。

功能目标及保护方向：

`Phi_k(A) = sum_c w_kc * F_kc(A, B_bar)`；

`u_k = gradient_A Phi_k evaluated at M_bar`。

`w_kc` 在求梯度前固定；不对gap计算过程反向传播。保护方向可单位化，非零正缩放不改变下面的半空间。总gap只记录，不在第一版用它控制服务器权重或步长。

这与旧C3不同：旧C3用gap重加权本地训练loss；这里本地A训练仍为原LA，gap只决定服务器聚合需要避免破坏的功能方向。是否比旧C3更好仍需结果，不因换了位置就宣称创新成立。

### 3.3 服务器怎样修正聚合

在全部A参数拼接的向量空间里，求：

`v = argmin_d (1/2)*||d-d0||_2^2`，满足每个活跃客户端 `dot(u_k,d) >= 0`。

含义：尽量保留普通聚合的更新，只去掉与客户端保护方向冲突的部分。至多30个线性约束；零更新始终可行。实现可解小规模约束/对偶问题，无需在服务器训练CLIP。

有效LoRA改动范数定义为各层拼接的：

`E(d) = sqrt(sum_layers ||scale * B_bar_layer * dA_layer||_F^2)`。

欧氏投影不保证这个有效范数不增大，所以再做固定上限：若 `E(v)>E(d0)`，令 `dP=v*E(d0)/E(v)`；否则 `dP=v`。正缩放不破坏上述一阶约束。若原有效更新为零，本轮不制造新的有效改动。

首版不另加可调混合系数或按测试集选步长。保存求解残差与实际提交的float32更新，不把求解失败悄悄替换成FedAvg而仍标记“保护成功”。

这是对局部一阶功能的约束，**不保证真实非线性模型或未来轮次绝不下降**。必须实测提交后的功能变化与后续恢复。如果投影频繁使A更新接近零，说明该版本主要靠冻结获得稳定，不能按预期方法故事结题。

### 3.4 为什么这比“客户端等权”更贴近目标

等权只改变系数，不判断更新是否损伤某个客户端已经获得的能力。本方案直接利用功能损伤方向修正共享A更新，同时保留普通FedAvg作为学习目标。

它不要求小客户端一定正确，也不假定所有非支持者更新都坏；真正保护什么由本地功能缺口决定。训练集拟合、保护目标相互冲突，以及B阶段已经丢失到本地无法恢复，都是可能失败的原因，需保留对应记录。

### 3.5 通信与隐私边界

算法服务器新增接收每客户端一个A维度的保护向量，以及是否活跃；本来就接收的 `delta_A_k` 和 `n_k` 不变。每个A向量18432个FP32数，约72 KiB；30个客户端每次A事件额外约2.11 MiB上传，未计协议开销。

类别编号、类计数和逐类gap可留在客户端侧，模拟离线分析另存审计信息，不能把审计表直接作为服务器决策输入。**梯度/功能向量仍可能泄露信息，不声称隐私保证；没有实现DP或安全聚合。**

现有E5的 `TrainingSideFeedback.observe` 上传逐类sum/count，不可原样复用后宣称“服务器看不到类别”。应复用其固定视图loader思路，重写客户端返回语义和可反向的功能计算。

## 4. 最小实验组：先三支，不做全排列

### 4.1 起点与续训长度

- 起点：对应拓扑已有S的第20轮A刷新结束状态，非测试最优检查点。它是本轮探索固定的早期点，不做20/40/60网格。
- 每支继续第21–100轮，共80个全局轮次，不是80个本地epoch。
- 每支B共240个全客户端epoch，A共70个全客户端epoch。
- CLT每支新增 `310*352=109120` optimizer steps；普通Dir每支 `310*354=109740`。功能计算额外成本另计。
- 第21–40轮可以查看方法行为；除运行失败外，不按官方测试趋势早停、择优改变参数。若停止一个坍缩候选，标记为未完成探索，不当作完成的保持结果。

### 4.2 R/P/K 的严格含义

| 组 | 当轮提交的 A 更新 | 主要用途 |
|---|---|---|
| R：常规续训 | `d0` | 同起点、新共同随机流的无保护对照 |
| P：功能保护 | `dP` | 方法候选 |
| K：同状态缩幅 | `dK=d0*E(dP_virtual)/E(d0)` | 排除只是缩小普通更新 |

K每轮从**自己的当前状态**计算一个未提交的P候选，获得对应有效范数；然后仅缩放自己的普通更新方向。若原范数为零，维持零改动。P的有效范数上限确保K不被放大。

这里“等幅”指在每个分支当前状态的局部反事实匹配，**不表示轨迹分离后P与K每轮实际范数或累计路径长度严格相同**。报告这些实际量，不能用“等幅”二字掩盖轨迹差异。

此外，在P自己的每个A起点，离线评价三个候选：普通 `d0`、保护 `dP`、同起点缩幅 `dK_virtual`。这给出真正同模型、同B、同本地更新、同有效幅度的即时方向比较，不需要再训练一个本地分支。该离线评价不反馈算法。

### 4.3 为什么还需要 R，不能直接用已完成 S 曲线

仓库的 `BridgeAudit.save` 保存了A/B状态和客户端更新，但中途事件没有保存Python/NumPy/Torch/CUDA训练RNG。现有 `load_global_checkpoint` 也明确不是完整训练事务恢复入口。

所以：恢复模型以后，为R/P/K固定一套新的、按seed/轮次/阶段/client派生的随机流。方法名不能进入随机种子；反馈与离线评价不能改变训练随机流。正常阶段与额外阶段仍各自重置优化器。

R是这个新随机协议下必要的80轮反事实续训，不是再跑100轮来重复证明旧S现象。旧S继续作为历史参考，不冒充严格配对轨迹。不需要用哈希来决定是否启动本研究。

### 4.4 后续次序与总量

1. **现在的优先任务：CLT的R/P/K三条80轮续训。** 不补跑E2/E3/J，也不先增加factor_roles的epoch。
2. 若P有有效信号：普通Dir补R/P/K三条相同续训。用于检验CLT的额外保持损失是否改善，而不是损害Dir制造差距缩小。
3. 若准备把“功能缺口选择”写成关键创新：增加一条CLT `P-flat`。在自身当前模型上计算gap，沿用P的活跃客户端判定规则，但在这些客户端内部用原本地频率 `pi_kc` 取代gap权重；同样计算保护梯度并使用同一投影。不照搬另一条P轨迹的活跃集合。这检验gap定向选择是否胜过笼统保护本地平均功能。总共最多7条80轮续训，分阶段决定，不一次铺开。
4. 初步成立后：固定方法，从初始化跑完整100轮；方法定义可明确前20轮为S式warm-up、第21–90轮使用保护，第91–100轮仅B。扩seed43/44；每个新seed包含对应R/K和关键基线，属于新重复证据，不是无理由重跑seed42。
5. 第二数据集/其他异质程度放在方法通过之后，不是当前阶段的前置条件。

不新增“把保护放B上”的整套实验作为当前门槛。若未来声称A比B更适合才补该特定对照；当前主张是A为有效干预入口，不是唯一入口。

## 5. 机制闭环怎样嵌入训练

### 5.1 两条数据通道严格分开

**训练侧反馈：**客户端自己的训练图片固定视图，用于gap与保护梯度，可能拟合训练数据。

**离线机制诊断：**原协议的200张训练池外Tail probe，不用于计算P、K、调投影强度或选轮次。由于它已经用于研究分析，不称为完全未见的最终盲测集。官方测试仅报告结果，不能反馈决策。

方法不用Tail标签，离线研究当然可以按预先定义的Tail20、支持客户端和非支持客户端分组，以理解作用对象。

### 5.2 保存每轮真实状态与阶段变化

至少保存：

- 本轮开始 `M_pre`；本地B终点 `M_k^B`；B聚合后 `M_bar`。
- 本地A终点或 `delta_A_k`；普通A候选 `M_Fed`；真实提交 `M_after`。
- 原始聚合 `d0`、保护修正 `dP-d0`、真实提交更新；有效范数、与d0夹角、活跃约束、求解残差、近零更新比例。
- 训练侧逐客户端gap均值/最大值、非零类数、保护前后Phi变化；这些是解释性日志，不是服务器按Tail筛选。
- 全部训练预算、反馈forward/backward、时间、显存、上传/下发字节。

每个候选的评价都恢复同一模型与模式；计算梯度时不可套用现有 `observational_model` 的整段 `torch.no_grad()`。

### 5.3 “本地获得—聚合保留—跨轮保持”如何计算

在客户端固定本地评价数据上，对每个client/class记录：

`local_gain_B = F(M_k^B)-F(M_pre)`；

`local_gain_A = F(M_k^A)-F(M_bar)`；

`unrealized_gap_after_B = F(M_k^B)-F(M_bar)`；

`unrealized_gap_after_A = F(M_k^B)-F(M_after)`。

gap同时保存有符号值与正部，不能只保留正部隐藏共享模型超过本地模型的情况。各类宏平均与本地样本频率平均都可报，但明确口径；不把本地增益简单相加冒充全局增益。

对固定的采样时点 `t=21,40,60,80,90`，冻结当时“本地功能比起点确有改善”的client/class集合，跟踪后续 `h=1,5,10` 轮的共享模型在同一批本地评价样本上的功能。不能每轮重新挑剩下表现好的类，从而制造保持率提高。

没有正本地增益时保持率记NA而不是0。除比率外必须报告分子、分母和有效client/class数量；比率可能小于0或大于1，不裁剪为漂亮的0–100%。这些是训练集代理，最终要与下面独立probe方向一致才支持泛化意义的保护。

### 5.4 独立 probe 上分解收益与损伤

先对所有轮次做低成本端点评价，得到B阶段、A阶段和未来B阶段的直接功能变化。完整归因只选固定早/中/晚A事件：`21,40,60,80,90`，以及下一轮B事件：`22,41,61,81,91`。不依据最坏的测试轮重新选点。

可复用既有 W/H/D/R 定义：

| 量 | 含义 |
|---|---|
| W | 有该类样本客户端的正向功能贡献 |
| H | 有该类样本客户端的负向功能贡献绝对值 |
| D | 无该类样本客户端的正向贡献 |
| R_neg | 无该类样本客户端的负向贡献绝对值 |

原代码字段名仍为 `R`；本协议写 `R_neg` 以免与常规续训组R混淆。用 `W+D-H-R_neg` 描述普通聚合的净功能变化。不要把非支持者一律叫“头部客户端”，也不要假定其贡献一律有害。

**新方法不能直接套旧归因而漏掉服务器修正：**旧 `attribute_run` 假定实际更新等于 `sum(q_k*delta_k)`，P不满足这一点。

采用两段路径：

1. `M_bar → M_Fed`：按原客户端更新积分，报告W/H/D/R_neg和数值重建残差。
2. `M_Fed → M_after`：服务器保护修正，直接测 `C_protect=F(M_after)-F(M_Fed)`，单独记录，不假装某个客户端的原始贡献。

因而实际阶段变化应记账为：

`DeltaF_A = (W+D-H-R_neg) + C_protect + numerical_residual`。

这样若改善主要来自负向损伤减少就如实报告，若来自正向功能增强也如实报告，不提前指定“正向更新减少”是唯一原因。按另一条路径拆分会有不同的贡献分配；这是受控路径归因，不是唯一的知识所有权分解。

### 5.5 后续B适配不能省略

保护在A提交瞬间有效，下一轮B仍可能损伤相同功能。报告紧接着的B阶段和固定1/5/10轮保持，而不是只展示投影后的一个好点。

若主要问题发生在B阶段，或者A即时保护不转化为长期收益，应明确当前“A聚合即时保护”的方法不足；不要声称所有遗忘已经解决。先用同一批记录定位问题，再决定是否需要跨阶段约束。

## 6. 结果判据：先锁口径，再看成绩

### 6.1 统一端点

- 保持：第21–100轮的峰到最终回落、峰到末20轮回落；并附固定窗口 `mean(Tail41..50)-mean(Tail81..90)`，不能只靠降低峰值制造“小回落”。

- E2/E3/J/S/CAPT仅作为已完成参考；R是新续训的主要因果比较对象。

### 6.2 pilot推进门槛（设计目标，不是已有结果或显著性阈值）

为了让“有效”不只依赖主观观感，第一版可冻结以下工程筛选门槛：

1. CLT P−R 的末20轮Tail至少 +1.0 pp，固定窗口回落比R少至少1.0 pp；同时列出峰值与最终值，拒绝仅靠降低峰值过关。
2. P−R Overall、Non-tail各不低于 −0.3 pp，Head/Middle各不低于 −0.5 pp。这是适配收益保留要求，不是声称任何下降都可忽略。
3. P相对K在Tail至少 +0.5 pp，或在相近Tail下Overall/Non-tail有明确额外收益；后者单独报告，不伪称达成原先Tail优势目标。即时同状态同幅比较也应有训练外probe支持。
4. 普通Dir P−R 的Overall与Tail各不低于 −0.3 pp；CLT改善不靠损害Dir产生。
5. 报告保护/原始有效范数比的分布和累计路径。若超过一半A事件有效更新不足原始的10%，先归类为“近冻结候选”，不能只靠尾类稳定宣布目标达成。

这些数值是本次设计预先固定的推进标准，尚未看新方法结果；正式结论仍展示全部连续效应和新种子变异。不能为刚好过关而事后修改门槛。

### 6.3 何时算机制闭环

同时满足以下方向，才把“保护客户端有效贡献”写成得到支持的方法机制：

- 相同当前状态下，P比普通候选及同幅普通方向更能保留客户端功能，且训练外probe也支持。
- 改善延续至后续B适配，不只保护提交瞬间。
- P的长期Tail保持优于R，并非单纯退回近冻结；K解释不了全部收益。
- 若强调gap选择的重要性，P优于P-flat；若相近，则把方法解释收缩为一般功能冲突约束，不硬称gap是关键创新。
- 数值归因重建覆盖实际提交更新，服务器修正单独记账，正/负贡献均展示。

若只有准确率改善而功能记录不支持，只能说“方法有效，解释尚未完成”。若只有训练侧Phi改善、独立probe和测试不改善，应考虑局部拟合或不合适的保护信号。

这是可检验的研究路线，不是已经完成的结论，也不因使用投影操作就自动构成新颖方法。
