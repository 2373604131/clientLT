# 正式对比实验与代码接入方案

日期：2026-10-05。状态：已核对本地入口与外部官方源码，本文为接入方案；新增对比训练入口尚未实现，未启动训练。

## 1. 冻结什么，检验什么

固定候选配方，停止同时扩展多个 B 分支，开始检验与相关方法的竞争力。冻结候选不等于已经证明 AB 必须作为最终完整方法，更不等于预先保证 SOTA。

- A：当前 Full-CP，保持权重 λ=10、分类权重 μ=1，保留来源优先级及历史目标。
- B：非尾类轮换采样、共享 C、尾类权重 w=0.35 的旧版 B；不采用本轮未改善主指标的 client/class 保护版本，也不切回定向 B。
- 主表分别列出 A、A+B。旧 B 的 donor 并集在已回收运行中始终为全部 30 个客户端，不把筛选有效或缺标签来源的独立贡献作为已经证明的结论。
- 保留已有直接校准对照。外部方法比较回答竞争力，不能代替这个关于 B 额外价值的内部证据。

## 2. 第一批方法

| 方法 | 主要回答的问题 | 本地与接入状态 |
|---|---|---|
| 标准 FedAvg + CLIP-LoRA | 相同基础模型上的普通联邦训练表现如何？ | 已有 ClipLoRA 及相关运行入口，需核验标准联合更新、聚合和协议；不能用内部 S 直接冒充 |
| CAPT | 与同领域的类别感知提示学习相比如何？ | 已有 trainer，历史启动协议仍需适配与官方核对 |
| FedPuReL，共享模型、LoRA 版本 | 与最相关的基础模型知识保持方法相比如何？ | 官方已有 LoRA 实现，本地尚未完成统一协议接入 |
| FedNTD，适配至 CLIP-LoRA | A 是否比已有联邦知识保持机制更有价值？ | 需依据官方实现接入；明确标为适配版本 |
| A | 核心方法本身是否成立？ | 已有冻结实现及 seed42、3407 结果 |
| A+B | B 是否在正式比较中提供有价值的增量？ | 已有冻结实现及 seed42、3407 结果 |

这是一组针对当前贡献的首批比较，不是对所有最新方法的穷尽清单。PromptFL 可利用现有实现补充提示学习参照；是否扩展其他方法，由相关工作覆盖决定，避免同时增加大量作用重复的运行。

官方来源：

- CAPT：[官方仓库](https://github.com/shihaohou/CAPT)。保持提示学习的算法结构，不强制改写成 LoRA。
- FedPuReL：[官方仓库](https://github.com/shihaohou/FedPuReL)、[CIFAR100 启动脚本](https://github.com/shihaohou/FedPuReL/blob/main/scripts/cifar100.sh)、[训练与评估代码](https://github.com/shihaohou/FedPuReL/blob/main/federated_main.py)。官方支持 prompt、LoRA、adapter；训练代码分别提供共享模型测试和个性化融合测试。
- FedNTD：[官方仓库](https://github.com/Lee-Gihun/FedNTD)。迁移其损失与教师模型规则到当前基础模型时，记录改动并检验数学实现。

FedPuReL 的官方 LoRA 默认配置与本项目不同，包含插入位置、投影矩阵、rank、精度及参与率等差异。不能仅因为都叫 LoRA 就宣称容量和预算相同。保留官方可训练结构的结果与严格匹配本项目结构的适配对照应明确区分，不能把删改后的方法标为完整原方法。第一批比较评估共享模型，不以个性化融合结果与本项目共享模型直接排序；若另研究个性化，应另建所有方法一致的评估任务。

## 3. 固定比较协议

1. 首先使用当前 CIFAR100 Client-LT 设置，30 个客户端、100 轮、全参与。直接读取固定的样本划分清单与客户端调度，不允许各个仓库自行重新随机划分。
2. 训练种子为 **42、0、3407**；当前划分与调度的协议种子保持 42。训练种子不等于划分种子。检查外部代码是否把 seed=0 当成未指定。
3. 使用相同 CLIP 预训练权重与测试样本、标签映射、输入预处理。不同提示/LoRA 结构记录可训练参数数目；涉及改变原方法结构的结果明确标注为适配。
4. 统一通信轮数、客户端参与和规定的本地基础训练预算。保持各方法必要的额外阶段，分别报告本地训练、教师前向、A 修正、B 校准等成本。相同轮数不能写成相同总计算量。
5. 首批超参数依据官方推荐与公开依据，在查看新比较结果前登记。若要调参，先确定所有方法共同的训练/验证划分和可比搜索预算，用验证集选择；不能用正式测试结果控制聚合、挑权重或挑最好轮次。
6. 如果新增验证集会改变当前训练样本，原 A/AB 结果不能直接混入新协议主表。先明确是否需要新协议，避免无意间使所有历史实验失效。

CAPT 历史记录包含不同聚合策略、客户端初始化/优化器规则和测试反馈使用方式，需要重新核对。移除测试反馈依赖时必须明确替代选择规则和适配标注，不能默默改变算法后仍宣称完全复现官方设置。

## 4. 统一读哪些结果

沿用本项目已经固定的主指标：第 81–100 轮正式提交模型的 Tail20 ACC 均值。同时报告同一窗口的 Overall、Head20、Middle60，以及第 100 轮结果和完整学习曲线。类别分组固定为本项目的 20/60/20 集合，不直接使用其他仓库按样本数阈值输出的 Head/Middle/Tail 数字。

先在每个种子内求末 20 轮均值，再跨种子报告均值、标准差及配对差值。20 个轮次不是 20 次独立实验，不能以此扩大统计样本量。尾类回落等轨迹指标作为保持证据，同时披露各组精度与成本。

当前 A/AB 的优势主要在尾类；已回收实验中 Overall 没有超过内部 S。外部比较也必须同时呈现这一取舍。只在相应数据集、协议和指标下确实领先时使用有范围的领先表述，不把尾类最好写成所有指标全面 SOTA。

## 5. 实施顺序与结果复用

1. 接通并验证标准 FedAvg-LoRA、CAPT、FedPuReL；FedNTD 用于 A 的保持机制比较。先做小规模运行检查，不用于选赢家。
2. 配置和实现核验后，执行固定的三个种子。不能因某个基线在 seed42 表现太强而删除该方法。
3. 当前已经回收 A/AB 的 seed42、3407；协议、源代码及评估指纹一致时直接复用。seed0 在本地归档中未见，应先检查服务器是否已有结果，再决定是否补跑。内部消融无需全部重跑。
4. 主设置比较完成后，扩展到另一种客户端划分，并增加第二个数据集的正式比较。普通 Dirichlet 用于协议适用范围，不能替代保持类别总量与客户端容量的固定边际干预。其他数据集需要先排除当前实现中的 100 类固定假设，不能只改数据集名称。
5. 若 A 有清晰优势而 B 增量小或成本不值，允许将 B 作为可选辅助或移入补充材料。若最相关保持方法在相同设置下全面更好，应据此定位 A 的必要修改，而不是继续无依据扩展 B。

## 6. 如何整理进当前仓库

由 Codex 接入并维护统一入口，用户不需要手动下载多个仓库再各自拼接结果。外部源码仍要获取或核对：优先取官方实现，固定提交版本，记录来源及本地修改；依赖冲突时用独立环境运行，由当前仓库统一生成配置、调度和收集结果。

建议新增的代码职责如下，路径仅为规划，尚未创建可运行入口：

| 部分 | 职责 |
|---|---|
| `configs/benchmarks/` | 固定实验矩阵、种子、协议、各方法超参数及官方版本 |
| `tools/benchmarks/` | 共用协议读取、各方法适配、输入/源码审计、结果转换 |
| `scripts/run_paper_benchmarks.py` | 计划、预检、训练、恢复的统一入口 |
| `scripts/collect_paper_benchmarks.py` | 完成状态检查、逐类指标重算、配对汇总和打包 |

现有 A/AB 冻结训练文件保持原版本，统一入口调用它们，避免新增基线破坏旧结果与恢复契约。外部方法通过适配层接收同一份协议；不简单把多个仓库的训练循环拼在一起。

实现验收至少包括：官方核心损失/梯度规则核对；客户端模型及优化器状态遵循各自方法定义且不意外串用；划分和调度指纹一致；测试数据不进入优化或策略选择；共享/个性化评估对象标记正确；逐类结果可重算；短程训练与恢复通过服务器 GPU 检查。通过这些检查后再提供正式的一行启动命令。

本次仅增加本方案文档，没有声称上述新入口已实现，也没有启动服务器任务。
