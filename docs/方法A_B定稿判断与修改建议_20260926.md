# 方法A/B能否固定：基于当前结果与实现的判断

日期：2026年9月26日。依据本地完整训练结果、既有审计及本次新增的逐轮CP诊断；没有修改训练代码或启动训练。

**判断：A的核心方法可以固定为接下来验证的主版本；B可以固定共享模型上校准、一次注入的结构，但当前完整配方还不适合定稿。A＋B整体也尚未达到可以停止验证、直接宣称最终效果的状态。**

这里需要分开三件事：固定算法定义，避免持续改变研究对象；固定默认配置，便于配对实验；固定论文结论，要求有足够证据。A的前两件事已有基础，第三件事仍有缺口。B还存在可从现有日志定位的方法问题。

## 2. 方法A：哪些可以固定

建议保留以下骨架：普通A本地学习与聚合 → 本地类别功能反馈 → 当前/历史目标 → 来源优先级 → 对共同A进行修正。

这条路线已有多方面的初步支持：

- 相对同频S有明确的尾类保持改善；并非完全放弃适配，Overall仍高于E3。
- 无CP旧版Full相对Current在同λ下Tail提高2.1100点，说明历史目标值得继续保留。
- Full-CP相对Flat-CP的Tail提高0.8800点、回落减少1.10点，来源优先级已有可用信号。
- 训练侧功能记录显示，修正确实改变了部分来源稀缺功能的待遇，并非只有一个最终分数差异。

因此，不建议现在重开新的历史规则、来源估计公式或另一套A/B结构。可以继续以Full-CP、λ10、μ1作为固定参考版本；这表示它是当前验证对象，不表示这些参数已被证明最优。

旧Full无CP也必须保留为对照：它在Tail和回落上略优于Full-CP。不能仅因为新版本多了CP，就默认新增项必须成为独立的论文贡献。

## 3. A的方法本身：优先处理目标取舍，不盲目增加保持强度

### 3.1 CP已生效，但其作用是软性取舍

本次重算了Full-CP μ1、μ3和Flat-CP μ1在第61–90轮的更新日志。

| 后期诊断 | Full-CP μ1 | Full-CP μ3 |
|---|---:|---:|
| 第2/3步CP激活比例 | 100% | 100% |
| CP与功能项梯度余弦，非零步骤均值 | −0.8785 | −0.8559 |
| 提交后训练LA相对普通提案的平均上升 | 0.0008746 | 0.0005654 |
| 有效更新范数/各自普通提案，逐轮均值 | 0.3773 | 0.4741 |
| A参数更新与普通提案方向余弦，逐轮均值 | 0.2025 | 0.3776 |
| 触及修正球边界的步骤数 | 0 | 0 |

CP在后期确实参与优化。较大的μ使分类损失上升减小，并使提交更新更接近普通提案；这与头中部适配部分恢复、尾类保持变弱的测试结果相容。这些是各自训练轨迹上的诊断，不能直接当作固定模型状态下的因果分解。

从μ1到μ3，Overall只增加0.0890点，Tail减少0.4650点，回落增大0.65点。因此，不建议把“继续增大μ”作为下一步默认动作。λ增大也会进一步改变保持与适配的取舍，不能期待单独调大保持项同时解决全部指标。

当前CP对整体训练LA风险的上升施加软惩罚。它没有承诺每个类别都不受损，也没有在这30个后期轮次将整体LA严格恢复到普通提案水平。这与实现定义一致，不是仅凭结果就能判定的工程错误。

### 3.2 若继续改A，先检查分类保护的粒度

当前CP按原样本量加权。重算其显式数据项系数，Many35约占81.35%，Medium35约占15.84%，Few30约占2.81%。这些是损失系数，不是梯度贡献比例；LA的调整和类别损失大小仍会影响实际优化作用。

因此，整体LA较好并不保证每个频数组都得到充分保护。Medium35是当前较明显的性能缺口，值得重点查看普通提案→功能修正这一步的分类变化。

**可检验的最小修改候选**：保留普通提案作为参照，研究按预先固定的训练频数组分别衡量分类损害，避免一组改善掩盖另一组下降。先在相同已保存状态上做短程对照，检查是否减少中频类损失并保留尾类功能收益；通过后再决定是否引入新版本。

这只是由现有结果提出的候选，尚未证明优于当前整体CP。当前证据也不要求立即重写CP：先补基本消融和重复seed，是比继续堆规则更优先的工作。若采用新约束，应单独记录版本，保留冻结v1用于比较。

### 3.3 历史目标与来源解释需要精确

历史记录的是连续五轮维持的功能改善水平，允许margin仍为负；初始分数只是登记参照，并未自动成为保持目标。因此，现阶段应说“维护已验证的功能改善”，不能保证所有预训练能力都有独立保护底线。是否加入初始能力保底，要先检验主要损失是否来自尚未登记历史的单位，不能仅因故事需要而追加规则。

来源优先级使用有效来源数的倒数。有效来源少不等于正向支持总量低，也不自动证明功能更容易遗忘。现有Full/Flat差异支持该规则值得保留，但解释仍需结合响应强度、更新幅度和真实功能变化。

## 4. A的方法效果：定稿前真正缺少的证据

1. **Current-CP正式消融。** 本地未发现完整结果。无CP的Current不能代替带CP版本；来源和历史的条件收益也不能直接相加作为独立贡献。
2. **与简单缩小更新的针对性对照。** Full-CP后期有效更新范数约为自身普通提案的37.73%，同时方向发生明显改变。现有结果不能排除部分保持收益来自缩幅。应在训练侧设定较小A更新或有效步幅匹配的控制，结合完整轨迹判断；不要用测试最优值反向匹配。
3. **固定实现后的配对重复seed。** 优先验证S、Full-CP、Flat-CP和Current-CP。固定数据划分下的训练seed验证，与跨划分泛化需要分别说明。轮次或类别不能当作独立seed。
4. **真实成本和适用范围。** 旧无CP Full的功能路径记录约占总耗时45%；这不是新fast-v2的测速结果。缓存和合批优化可继续，但减少见证、更新频率或步骤属于算法条件变化。最终按论文范围补外部基线及普通Dir结果，不用旧matched Dir代替。

完成这些验证后，即使仍存在小幅总体精度代价，也不意味着A必须被推翻。关键是保持收益是否稳定、是否超出简单弱化更新，以及代价和成本是否被清楚报告。

## 5. 方法B：共享校准结构可以保留，覆盖与筛选需要继续处理

### 5.1 首要问题是校准覆盖和收益—代价目标

共享B相对A-only的Few30有改善，但Medium35下降。进一步还原校准数据项发现，Tail20占50%，Head20约占33.51%，Middle中的Many15约占8.72%，Medium35只占7.13%，Middle中的Few10约占0.64%。

这说明“尾类/非尾类各一半”的目标，并没有保证非尾类内部的充分覆盖。该事实不能证明7.13%的系数造成了全部Medium下降，但给出了比继续加大学习率更具体的修改方向。

仓库已经实现了针对这点的shared-tradeoff版本：非尾样本按本地类别轮换抽取，并预定比较尾类损失系数w=0.5、0.35、0.2。**这条方向合理，优先回收或完成这三组，而不是再增加新模块。** 本次检索尚未发现其本地正式结果或新损失轨迹。

比较顺序应保持清楚：新w=0.5相对旧共享B检验覆盖变化；新w=0.35/0.2相对新w=0.5检验组间权衡。降低w本身不能保证中频类获益，也不能把它当作改变了客户端聚合权重。

目前反馈仍来自原有的22个尾类持有客户端。类别轮换只能改善这些客户端内部的覆盖；如果剩余损失来自反馈池之外的类别分布，再考虑是否需要额外保护反馈，并单独计入成本。现在没有理由直接扩大所有反馈端。

### 5.2 donor筛选在共享候选池上没有产生区分

8次迁移事件中，601条候选关系经过筛选后保留406–449条，但对所有接收端取并集后，每次仍是全部30个客户端。代码随后在同一个全体donor池上优化共享C，没有按各接收端原先的名单分别屏蔽来源。

因此，在这些事件中，筛选后的共享候选集合与直接采用全体客户端相同。当前结果不能将收益归因于“筛掉了不利的全局donor”。这不意味着整个B无效：C仍然可以在联合校准中区分、变换不同更新；需要明确哪个部分实际承担作用。

后续需要作出一个明确选择：

- 若保留筛选作为关键机制，就应检验目标相关的有益/有害反馈是否真正改变最终共享残差中的来源使用，而不仅用于形成最终仍为全集的候选池。
- 若全池联合C重组本身已足够有效，可以简化冗余筛选，并把方法准确表述为目标反馈指导的共享更新重组。

这首先是代码和同状态诊断可以回答的问题，不必立刻为一个实际完全相同的全池再跑多组100轮。进一步设计关系约束时，仍应对同一个共享候选模型反馈，避免重新回到各端使用不同候选再拼接的旧实现。

### 5.3 暂不把学习率、步数或迁移幅度直接调大

当前迁移已经进入共享模型：有效LoRA改动范数约为普通B更新的1.34–2.73倍，8次事件均完成。训练侧Tail LA大多改善，同轮随后A也未将这些平均LA改善立即抹去。因此，“根本没有加进去”“被小客户端权重冲淡”“马上被A全部覆盖”都不是这版结果支持的主要解释。

下一步先检查新实现的同一固定校准池损失轨迹，比较C=0、第一步后、第二步后的目标与分组损失。旧日志两步使用不同batch，不能直接相减来判断优化是否充分。

只有在相同目标上看见优化不稳定或预算不足的证据时，再考虑调整学习率或步数。范数较大本身不能证明过冲；也不能据此承诺加正则或缩步就会改善。

## 6. B的方法效果：目前不足以承担强独立贡献

现有B结果需要面对三个事实：

- 对A-only的Tail增益只有0.1525点，尚无跨seed稳定性证据。
- Medium35下降0.1400点，当前没有补齐A相对S的中频学习缺口。
- Tail峰值回落与A-only同为1.00点，目前只能说尾类水平略有抬升，不能据此说B进一步解决了尾类遗忘。

最终应验证：在固定A上，B的收益能否稳定复现；是否优于相同训练数据和反馈预算下的简单额外更新；donor更新成分与C变换是否提供独立价值。简化方案是用于检验必要性的对照，不等于现在就把B改写为直接训练B。

B本身的已记录事件计时约222秒，占该次16.40小时运行的0.38%。该比例不是跨硬件端到端消融，但至少不能把整次长训练耗时归咎于B。因此，是否保留B应结合稳定收益、模块必要性和通信反馈代价判断，不能只因提升小就认定计算不划算。

如果完成当前覆盖/权衡优化和配对验证后，B仍只有接近零的小收益且独立作用不清楚，应把它降为附录探索，或暂从主贡献中移除。论文结构应服从结果，不应为了凑齐A/B而维持一个证据薄弱的模块。

## 7. 推荐执行顺序与停止条件

| 顺序 | 工作 | 暂时固定什么 | 依据什么决定下一步 |
|---|---|---|---|
| 1 | 固定A参考版本，回收Current-CP及已有服务器结果 | Full-CP λ10、μ1；主训练协议 | 补齐基本组件证据，避免重跑已有组 |
| 2 | 回收/完成B覆盖＋w三组 | A、donor＋共享C结构、样本预算 | 是否减少Medium代价并保留Tail/Few收益 |
| 3 | 核对B同池损失与donor池实际作用 | 同状态、同反馈数据 | 决定优化不足、目标覆盖或筛选冗余哪个问题需要修改 |
| 4 | 做少量针对性控制 | A缩幅参照；B简单额外更新/必要组件对照 | 检验复杂设计是否有独立价值；不展开旧路线全套 |
| 5 | 最终候选统一执行版本，做配对seed | 不继续同步改A与B | 依据重复实验的效果、代价和预算决定正式主表 |

若A保持收益稳定且超出简单更新控制，可以将A正式固定，即使仍存在需要如实呈现的取舍。若Current-CP/Flat-CP结果不支持某个组件，应简化对应主张或方法，而非默认追加规则救回预设解释。

若B获得稳定的条件增益并通过必要性对照，可作为辅助模块固定；若增益依赖单个seed或以明显组别损害换取极小总体变化，就继续缩减其论文角色。

## 8. 一个需要同步修正的文档口径

当前`utils/cliplora_sfra.py`和方法A冻结规范表明：QR用于来源响应计算，修正变量z与完整A参数向量同维，实际修正在完整A空间进行。`docs/cliplora_b_shared_tradeoff.md`的学习率表把A修正写成“提案子空间坐标”，与当前实现不一致。

这里应修正文档表述，不应为迁就旧文字而修改已经运行的算法。本次仅记录此问题，未改写原规范或训练实现。
