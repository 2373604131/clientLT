# 方法 B：来源反馈与组合损害的实验设计

日期：2026-10-03。状态：实验设计稿；尚未修改训练代码、启动实验或验证候选更新规则。本文中的系数是固定的首轮开发配置，不是已知最优值。

执行顺序更新：结合后续关于“同一客户端内多个类别共享 C”的讨论，本文的 S/H 三组方案暂缓直接启动。当前优先执行[共享更新的客户端内类别冲突实验设计](方法B_共享更新类别冲突实验设计_20261003.md)：先比较客户端内分组平均保护与客户端—类别保护，来源反馈调权作为条件性后续。本稿保留为来源反馈候选的技术说明，不是另一个需要同时启动的实验清单。

## 1. 要回答的问题与已有证据

核心问题：同一个共享更新，能否更充分使用有利于目标尾类的来源成分，同时减少对其他类别的损害？这里的“成分”指 donor 更新经独立 C 变换后参与共享残差的部分，不声称已经分离出可解释的语义知识。

现有基线为轮换采样共享 B、w=0.35。seed42、3407 的 Tail20 第81—100轮平均精度，相对 A 分别提高0.2225、0.1300个百分点；同数据、同优化步数、匹配有效更新幅度的直接校准对照分别提高0.3225、0.2175个百分点。B 的增量和 donor 重组的额外价值应分别判断。

当前16次 B 事件的 donor 并集都是30个客户端。逐类别探测关系没有进入后续共享 C 的更新规则。32个 C 优化步骤都降低了记录的固定反馈池目标；没有观察到明显发散，但不能据此认定已收敛或步长、步数最优。

历史 directed 与 positive/zero 改过反馈端、样本范围、视图、损失或 C 参数化，不能充当本次基线上的单因素对照。尤其不能把下面的方案称为旧 positive/zero 的重复验证。

## 2. 固定范围

- A 保持 Full-CP、lambda=10、mu=1 以及当前历史/来源规则。
- 数据、客户端划分、普通本地训练、FedAvg、初始化及调度不变；固定原 Tail20，不扩成 Tail30。
- 沿用旧共享 B 的接收端及候选池生成规则。现有数据中反馈端为22个；不缩成协议尾部3个客户端，不新增 Top-K。
- 每 donor、每模块独立 C；固定 rank4、6模块；C 每事件从零开始；共享残差仍为 R=mean_j(DeltaB_j C_j)。
- 迁移轮次30、40、50、60、70、80、90、100；两步 Adam，lr=0.3，C 正则0.001。
- 保持 class-cyclic 采样、尾/非尾权重0.35/0.65、训练图像变换和反馈批次生成规则。各组每事件使用相同的样本身份；后续模型及来源探测值允许随轨迹分化。
- 所有样本始终用同一个真实共享候选模型做前向；推理不按真实类别选择 donor，不增加类别专属模型。
- 仅使用训练侧反馈；测试数据不用于选择 donor、设置类别权重、更新保护参照或决定是否提交。
- 固定第二步提交，不新增测试门控、回退或逐轮离线重放。

### 3.1 S：让逐类来源反馈进入 C 的更新

这是待验证的软梯度调节规则，不预设它优于当前端到端梯度。原模型梯度已经含有来源响应信息，探测得到的额外先验也可能冗余或带噪声。

1. 沿用现有同一普通聚合模型上的0.1 DeltaB_j探测。对类别c，汇总持有c的接收端上的损失下降，按实际探测样本数计算类内均值，得到带符号的g_cj。
2. 对缺少类别c标签的候选来源集合E_c，构造q_cj=1+0.5*tanh(g_cj/(mean_{j in E_c}|g_cj|+1e-12))，再以E_c内的q均值归一化，得到a_cj。集合外a_cj=1；空集合或全零分数退化为1。
3. 对尾类c贡献到donor j的C梯度乘a_cj，再汇总；非尾类分类梯度、C正则梯度和H梯度不乘这个系数。
4. 两步都在实际共享候选上重新计算分类梯度；g和a在当次迁移事件内固定并停止梯度。下一次事件重新探测。

若G_jc是原0.35尾类损失中类别c贡献的C_j梯度，则更新使用：

`G_j = sum_c a_cj G_jc + G_j_non_tail + G_j_regularizer + beta G_j_H`。

这里保留原客户端/组内样本权重，不额外把基础分类损失改成类等权。归一化保持系数平均尺度，不能保证实际梯度或有效更新范数匹配；这些必须记录。

该规则保持所有来源可用，不把原始更新提前合成固定类别基底，不构造正响应教师，也不要求正反馈 donor 对所有类别有益。所有训练前向的参数值相同，仅训练梯度如何汇总不同。它是更新规则的改变，不能误写成仍严格沿原标量损失做梯度下降。

实现可以按客户端/类别计算原始梯度后合并，避免为每个donor重复CLIP前向。按类求导、聚合统计仍可能增加开销；必须记录真实前后向量、同步量和时间，不能宣称总计算完全一致。

### 3.2 H：惩罚真实组合后的逐类损害

在每个迁移事件中，以实际普通聚合模型theta0作为参照。对当步固定反馈样本，计算类别c的类内平均LA损失ell_c(C)，并缓存同一批图像、同一变换下的ell_c(0)。先跨客户端汇总该类的损失与样本数，再求类均值。

定义当前批次实际观测的尾类和非尾类集合T_s、N_s：

`H(C) = 0.35 * mean_{c in T_s} relu(ell_c(C)-ell_c(0)) + 0.65 * mean_{c in N_s} relu(ell_c(C)-ell_c(0))`。

空集合对应项为零；未采到的类不虚构观测。基础分类损失和C正则不变，额外系数beta=1固定，不做beta网格搜索。类内均值及损害激活需按实际样本总数计算，不能逐客户端先做ReLU再误称全局逐类损害。

含义：改善类别仍由原分类损失奖励；损失高于迁移前参照的类别获得额外纠正压力。这个参照只约束本次迁移的附带损害，不替代A的历史功能保持。

使用线性单侧惩罚，以保持与LA损失一致的量纲。C=0时H梯度为零；两步预算下，它主要在第二步响应第一步引起的损害。第一步后若没有激活，需记录为“本预算下约束未介入”，不能据此断言类别间没有冲突。第二步仍可能产生新损害；本设计不是硬保证，也不追加保护专用优化步骤。

H按类汇总的反馈，仍只是训练侧代理，不是逐类测试精度保证。不能把平均训练损失下降当作泛化成功。

## 4. 自动记录的结果，不要求额外逐轮重放

### 最终效果

- 主指标固定为提交模型第81—100轮Tail20测试ACC均值。
- 同窗口报告Overall、Head20、Middle60、Non-tail80；末轮单列。
- 相对A及旧B的每类精度差，改善/持平/下降类别数；报告负差总量及最差类别退步，避免只看类别计数。
- 按种子列配对差。不能把轮次、类别或接收端事件当作独立训练重复。

### 解释机制所需的轻量记录

- S：g与a的分布、eligible关系数、实际梯度变化、同并集不同关系是否改变C更新。若全部a接近1，应判为干预弱，不能强推“来源反馈无用”。
- H：每步激活类别、分组损害量、H梯度范数与分类梯度范数；在旧B上也只读计算同样指标。
- 每步有效残差范数与普通更新范数之比、C范数、反向图像数、前向图像数、同步数、通信估计和耗时。
- 上述训练记录在事件中自动保存，汇总后解释；不新增手工逐轮重放、不按测试结果挑事件或检查点。

## 5. 只有候选有收益，才补对应机制对照

不是把本节所有组无条件启动。每个对照只跟随其需要检验的主张。

### 5.1 来源关系打乱：仅当10或11胜出

选定候选只把每类E_c内的a_cj随机置换，仍乘到原donor张量对应的梯度上。保留缺标签资格、来源集合、系数分布、数据、参数量和更新步骤。置换由训练种子、事件、类别决定，不使用测试信息；不置换donor张量和C索引来抵消打乱。

这比“统一缩小更新”或“删除来源”更接近检验对应关系：正确的反馈应比统计分布相同、对应错误的反馈更有用。若二者接近，则不能把收益归因于准确识别谁帮助谁。若梯度幅度差异仍很大，应承认这一解释边界。

### 5.2 幅度对照：仅当要把H的收益归因于方向改善

如01或11显示损害减少，必须先看有效更新范数。若要声称它改善了组合方向而不只是缩小了更新，则对相同S开关、不含H的版本，匹配候选每步有效残差范数后完整训练。可复用现有“已完成候选提供训练侧范数轨迹”的诊断办法，不读取测试指标决定幅度。

该组是依赖候选轨迹的诊断对照，不是独立算法。跨轨迹按事件/步骤匹配范数不等于全部后续状态相同；范数为零、重建为零和数值容差需显式记录。

若幅度对照得到同样结果，应优先考虑简单的步幅控制，不必保留逐类损害模块。若没有做该对照，结论只能是“H整套更新规则带来收益”，不能进一步锁定方向冲突机制。

### 5.3 直接校准：候选准备定稿前

用选定候选的实际反馈样本、基础LA权重、H设置（若启用）、两步预算及其训练侧有效范数轨迹，重新配套直接残差校准。旧版直接校准结果不能替代新候选的匹配对照。

直接残差没有donor索引，因此不套用S；也没有C矩阵正则。此对照比较整套来源利用方式与直接校准，不能唯一隔离C参数化的因果贡献。可学习参数量、全部计算和正则形式并不完全相同，应如实报告。

若新B只胜过旧B、仍不优于匹配直接校准，不能把“增强尾类的额外迁移价值”写成已验证。可以讨论其他已证实的成本/类别取舍，但不得事后用另一指标替换本次Tail20主指标。

## 6. 根据结果修改方法

| 结果模式 | 能支持的结论 | 对B的处理 |
|---|---|---|
| 10提高，01无收益；正确反馈优于打乱 | 本设置下逐类来源信息有附加价值 | 保留软来源反馈；不强加H、不回到硬Top-K |
| 01提高，10无收益，11不再提高 | 组合损害控制更值得保留；额外来源先验未证实 | 保留H，放弃新增S；筛选创新主张收缩，C价值仍看直接校准 |
| 11提高且分别优于10、01 | 来源利用与损害控制可能互补 | 同时保留S/H，复核正确对应与幅度因素 |
| H降低损害但没有提高Tail20，更新同时明显缩小 | 可能主要是更保守，不等于增强学习 | 不直接定稿；幅度对照决定是否用更简单的控制 |
| S提高，但打乱也同样提高 | 未证明准确的来源—类别对应是原因 | 不保留定向筛选的机制主张，优先简化 |
| 训练代理改善、测试没有改善 | 本候选未显示可泛化的额外支持 | 不按训练得分宣布成功，不继续单纯增加惩罚或步数 |
| 新组均不优于旧B，且干预确实生效 | 当前两种修正没有支持，不能断言所有迁移无效 | 保留旧B为参照，停止扩模块；收缩主张或再单独研究C限制 |
| 候选优于旧B但不优于匹配直接校准 | 更新规则有改善，donor重组的尾类额外价值仍未建立 | 不以此固定“迁移优于额外校准”的结论 |

## 7. 开发与确认顺序、停止规则

1. 首轮只新增10、01、11，seed42，各100轮。A、旧B数据复用条件见第3节。
2. 先按固定主指标与副作用判断是否存在值得保留的候选；若没有且干预有效，停止本轮，不追加所有控制组。
3. 对一个候选补所需机制对照。不要同时保留多个候选继续扫参数；若结果仅显示取舍，完整报告而不勉强选赢家。
4. 机制证据成立后锁定配置，用用户已指定的0、3407做配对复核，包含候选、关键机制对照与匹配直接校准。需要哪条主张，就保留对应对照；不默认把四组因子实验全部重复。旧A/旧B可在协议与执行一致时复用。
5. seed42属于开发；3407的旧结果也已经看过，不能称完全未见的保留测试。三个种子用于配对重复与稳定性描述，不足以对很小差别作强统计保证。

建议在新结果产生前冻结以下工程筛选门槛：相对旧B，开发阶段Tail20提升至少0.10个百分点，Overall下降不超过0.05个百分点，且相对A保持正向尾类增量，才进入后续成本更高的确认。它们是本项目的预设实用门槛，不是论文通用标准或显著性检验。

最终确认建议要求0和3407的Tail20配对差都为正、两者平均提升达到上述实用门槛，同时各自Overall下降不超过0.05个百分点；机制对照也应方向一致。若仅一个种子成功，报告不稳定，不能称已固定。不要求每个类别都不下降，但需披露负收益总量和最差退步，不能用均值遮盖明显副作用。

任何超参数调整均产生新版本，不能在看过结果后追改本版成功标准。本轮不新增Tail30、不更改A、不自动补更多种子，也不保证这些候选会成功。
