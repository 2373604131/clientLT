**CAPT：seed 42 六组实验统一收集与分析**

先收齐六次运行的原始产物，再根据 `command.json` 确定实验分组。目录名称不能代替实际配置。本收集脚本只读取实验文件，不训练，不覆盖已有压缩包。

将 `scripts/collect_capt_results.py` 同步到训练服务器，在仓库根目录运行：

```bash
python scripts/collect_capt_results.py --roots output/cifar100_LT --list-only
```

脚本默认只选择 seed 42、CAPT、cluster、开启每客户端全局参数恢复的运行。它打印划分、λ、聚合频率、优化器重置状态和原目录。如果六组中包括未开启全局参数恢复的原始 cluster 或 FedAvg，应另外提供其目录与配置，不能使用此过滤结果冒充已收齐。

如果恰好找到目标六组：

```bash
python scripts/collect_capt_results.py --roots output/cifar100_LT --out output/capt_six_seed42_results.zip
```

如果搜索到了其他历史实验，用三个实验父目录限定范围；下面路径是占位示例，必须替换成实际目录：

```bash
python scripts/collect_capt_results.py --roots output/cifar100_LT/EXPERIMENT_A output/cifar100_LT/EXPERIMENT_B output/cifar100_LT/EXPERIMENT_C --out output/capt_six_seed42_results.zip
```

也可以在 `--roots` 后直接列六个单次运行目录。默认要求恰好找到六组，否则打印目录后停止打包，防止遗漏或误收。不需要改训练配置，不需要重跑，也不会启动其他种子。

把 ZIP 复制到当前本地仓库的 `output/` 下并告知路径即可。没有必要手工复制终端末尾或仅提供截图。

ZIP 中有：

- `summary.csv`：最终 Overall、非尾类、尾类、Macro-F1、头尾调和平均；最后 20 个外层轮内的实测均值与实测数量；峰值及对应轮次；训练轮、聚合次数与关键配置。
- `manifest.json`：六组原目录、完整命令、实验记录的源文件哈希、收集文件 SHA256、完整性检查警告。
- `runs/run_XX/`：原始日志、命令与完成记录、逐轮和逐类 CSV、客户端类别矩阵、划分指纹、实际客户端顺序、提示参数快照和找到的日程文件。

不收训练图片及完整模型检查点。提示快照足够开展参数变化分析，但不能代替含视觉耦合模块的完整模型做重新推理。

**统一分析口径**

1. 先建立六行配置表，核对 seed、划分、λ/α/β、用户数、参与率、本地 epochs、学习率、骨干、全局参数恢复、优化器重置、MAB/固定聚合、代码版本。相同划分下比较客户端类别矩阵和实际参与顺序；不能只看 seed 相同。
2. 以最后服务器模型为主结果。分别写明最后实测外层轮和聚合次数；MAB 运行最后一行不一定来自第 100 轮。补充最后 20 个外层轮内实测均值，不混成“最后 20 次评测”。峰值仅作补充，总体峰值和尾类峰值可能属于不同模型。
3. 同一划分内比较不同协议。同协议跨两种划分比较拓扑敏感性。若三套协议分别是保留 MAB、固定每轮聚合、再重置优化器，可以依次做配对差值；固定聚合同时去除了测试反馈，差值不能全部归因于聚合次数。
4. 同时按外层训练轮和服务器聚合序号画曲线。100 个外层轮不一定是 100 次通信。同一聚合序号也未必具有相同本地计算量，尤其保留优化器状态时，跳过聚合的轮次仍可能留下间接影响。
5. 按同一批尾类的聚合资格做逐类配对分析，检查之前的 10 类获益是否保持、无资格尾类是否改善、非尾类损失是否减轻。提示变化与准确率变化可支持机制解释，独立因果贡献仍需匹配消融。
6. 只报告 seed 42 的描述性结果，不把六组不同配置当成六个随机重复，也不把轮间标准差当成多种子置信区间。

若两组 fine-Dirichlet 仅改变了 specialization λ，它们没有构成 λ 消融：该划分不使用 λ。应继续核对代码、数据和其余参数，判断它们是不是同配置重复运行。

现有 `tools/analyze_capt_global_start_results.py` 专门审计最初两组 MAB 运行，包含“两组聚合轮次相同”等特定断言；不要只替换路径就拿它直接处理六组。收齐结果后应使用各组实际协议进行联合分析。
