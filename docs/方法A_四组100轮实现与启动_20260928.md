# 方法A：seed42四组补充实验实现与启动

本轮实现范围：Shuffle-CP、Current-CP、Plain-Hold、Norm-Matched，四次独立100轮训练。复用已有Full-CP λ10、μ1；B迁移关闭，普通B本地训练保留。没有增加μ/λ搜索，也没有增加其他训练组。

按用户2026-09-28要求，仅做代码静态审查、Python语法解析及差异格式检查，不跑冒烟、短程或GPU测试，不增加哈希验证门槛。底层旧日志可能仍记录原有指纹字段，新入口不使用这些字段作验收。尚未在服务器执行新100轮，不能把静态审查写成运行通过。

## 四组分别改变什么

| 命令方法名 | 唯一有意干预 | 与Full-CP比较回答什么 | 关键记录 |
|---|---|---|---|
| `shuffle-cp` | 相同类别内，在活跃的客户端—类别单位间重新分配原权重 | 正确的细粒度来源对应有没有用 | 原/新权重、供体索引、每类总量、可交换及实际改权重数量 |
| `current-cp` | 历史不再抬高目标，也不再激活功能单位 | 历史目标贡献有多大 | 当前/最终目标、支持/活跃掩码、影子历史 |
| `plain-hold` | 不用来源响应增强目标，不用来源权重 | 相对普通功能保持，来源方案有没有额外价值 | 更新前、普通提案、修正后margin及分类损失 |
| `norm-matched` | 普通A增量各层共乘一个标量，匹配Full同轮有效范数 | 相同更新长度下，修正方向是否值得 | 普通/目标/实际范数、系数、误差、是否放大 |

三组功能修正沿用λ10、μ1、原三步修正、步长0.1、原半径及尺度。等幅度组不做功能修正或CP，它保留普通方向。各组都从Full保存的初始模型出发；之后所有B、普通A提案及历史属于本组自己的训练轨迹。

共同日程：seed42、protocol42、Client-LT，30客户端全参与；每轮B训练3个epoch；1—90轮每轮额外A训练1个epoch，91—100轮B-only。数据划分、本地样本顺序、见证样本、执行模式和训练参数均沿用参考运行，不改成此前短实验的fast-v2配置。旧Full是标准执行时，新组也用标准执行，不能按fast-v2短实验时间估计本轮耗时。

打乱规则在开跑前固定：独立seed420928为每类生成一次单位顺序；每轮过滤出活跃单位，沿该顺序循环换位。相同活跃集合的对应不随轮次随机变化。整体权重分布和每类总权重不变；单个活跃单位无法交换，权重相等时换位也可能没有实际干预，都如实记录。它只回答类内对应问题。

普通保持目标为 `T=max(F_postB_preA,H)`，没有有效历史时 `T=F_postB_preA`；所有单位均活跃且等权。没有`.5*u`增强，也不计算来源响应/来源QR。为保留相同sigma定义，仍计算完整功能梯度范数，成本计入。此组是预先确定的普通保持控制，不代表所有可能的蒸馏方法。

等幅度以所有层合并的 `sqrt(sum_l ||0.5 * B_l * ΔA_l||_F²)` 为准，B取本组本轮普通B聚合后的状态。只借Full第1—90轮的90个标量，不借其后续模型。系数大于1照常放大并标注；不能偷偷截断成缩小。零提案不能匹配非零目标时明确报错，不能用替代状态凑结果。

## 服务器启动

把以下六个Python文件按相同相对路径同步到服务器项目：

- `federated_main.py`
- `utils/cliplora_sfra.py`
- `utils/cliplora_la_control.py`
- `utils/method_a_supplement.py`
- `tools/sfra/supplement.py`
- `scripts/run_method_a_supplement.py`

以下命令均在服务器项目根目录、已激活`clientlt`环境下执行。默认数据目录为`DATA`，参考运行是：

`output/cifar100_LT/sfra_cp/seed42/client-longtail/full-cp/lambda10_mu1_protocol42`

逐组启动，一行一个：

```bash
python -u scripts/run_method_a_supplement.py --stage train --method shuffle-cp --seed 42
```

```bash
python -u scripts/run_method_a_supplement.py --stage train --method current-cp --seed 42
```

```bash
python -u scripts/run_method_a_supplement.py --stage train --method plain-hold --seed 42
```

```bash
python -u scripts/run_method_a_supplement.py --stage train --method norm-matched --seed 42
```

或者用一条命令依次跑完四组；与上面四条二选一即可：

```bash
python -u scripts/run_method_a_supplement.py --stage train --method all --seed 42
```

输出是`output/method_a_supplement_seed42/<方法名>/`。已完成的组会跳过；存在正式检查点的中断组重敲同一命令自动续跑。各组从独立初始模型开始，不是第60/80轮接着跑5轮。不要把同一组同时启动两份。

如果参考运行或数据实际放在别处，在训练命令追加`--source-run 实际Full目录 --data-root 实际数据目录`。原始Full训练目录应保留模型，只有CSV/JSON的轻量分析包不够恢复预测；入口会在训练前检查文件存在及配置值，不会跑短测试。

必需的旧模型：`checkpoints/base_model.pt`，第58、59、60、78、79、80、90轮`sfra_rounds/rXXX/commit.pt`，第100轮`events/r100_c000_main_normal_B/state.pt`。完整Full普通训练原本会保存这些文件。

## 跑完以后

默认一条命令汇总并打包：

```bash
python scripts/run_method_a_supplement.py --stage pack
```

生成`output/method_a_supplement_seed42_results.zip`。这就是回传分析的结果包，包含逐样本预测和训练侧功能数组，不包含大型模型权重。

脚本按固定路径自动找旧S、Flat-CP和两组短程结果，不按精度挑运行。优先查服务器原训练路径，其次查本地已回收分析包。若旧结果移动过，可显式指定，仍只是读结果，不启动训练：

```bash
python scripts/run_method_a_supplement.py --stage pack --baseline s=output/cifar100_LT/la_control/seed42/client-longtail/s/tau1_a1_protocol42 --baseline flat-cp=output/cifar100_LT/sfra_cp/seed42/client-longtail/flat-cp/lambda10_mu1_protocol42_fast --short-root output/method_a_diagnostics_a60_fast_v2_f128_c4 --short-root output/method_a_diagnostics_a80_fast_v2_f128_c4
```

四组训练完整与所有证据完整分别记录在`analysis/suite_status.json`，不会因为四组结束就冒称所有旧基线与来源分析齐全。已有Flat是fast执行、Full是标准执行时，会标记为执行版本不同的历史参考，不伪造数值等价证明，也不会自动要求补跑第五组。

## 一次训练带走哪些答案

| 输出 | 用大白话说看什么 |
|---|---|
| `analysis/last20_summary.csv`、`full_minus_controls.csv` | 后20轮Tail、Medium、Overall分别赚了多少、损失多少；另有末轮和90→100变化 |
| `analysis/metrics_100rounds.csv` | 全部轮次曲线；峰值回落仅辅助，不拿最好一轮当主结果 |
| `analysis/control_diagnostics.csv` | 打乱是否真换了权重、缩放是否真匹配、功能修正执行几步 |
| `analysis/witness_classification_harm.csv` | 按预定训练频数组分开看，修正怎样改变普通A提案的分类损失与功能margin |
| `analysis/learning_and_forgetting.csv` | 每轮各组错→对、对→错、初始化正确/错误样本后来的状态 |
| `analysis/origin_own_trajectory.csv` | 每组自己稳定学会的旧/新能力保留情况；各组样本可能不同，仅描述轨迹 |
| `analysis/origin_common_short_windows.csv` | 用同一起点、同一批样本比较已有六条短程分支的旧/新能力保持 |
| `analysis/costs.csv` | 本地训练步数、功能前后向及通信量；等幅度明确依赖Full的幅度序列 |

等幅度任务自动补评估已有Full的0、58、59、60、78、79、80、90、100轮模型，只做前向预测、不做训练。新四组都保存0—100轮的逐样本ID、类别、预测、正确与否、CE、LA和margin，以及每轮正式LoRA状态。测试数据不参与目标、权重、映射或缩放选择。

共同短程队列固定为：初始化预测正确/错误，且在58—60或78—80连续三轮正确；随后检查旧分支65/85轮。两类队列都在干预前定义，记录样本分母；不根据终点筛样本。第0轮只叫“任务初始化已有能力”，不自动称为CLIP零样本能力。

## 静态审查记录

| 要求 | 代码落点与审查结果 |
|---|---|
| 只增加这四类、固定42、直接100轮 | 新launcher只接受四类及all，seed choices只有42；stop固定0；runtime再检查配置 |
| 复用实际初始化及数据 | runtime严格加载Full的base_model；沿用原命令/partition/schedule；逐条比较实际划分和见证；不使用哈希验证 |
| 原A公式不被改写 | 原来源测量与目标构造只抽成两个可覆盖函数；原三步、CP、投影和历史登记主体沿用 |
| Shuffle不改变类别总预算 | 仅活跃同类循环换位；逐轮检查权重多重集和类总量；数组保存供体映射 |
| Current没有历史泄漏 | 继续使用原current-cp目标分支；额外检查active==supported，活跃target==current_target |
| Plain没有来源增强残留 | 完整梯度经零列基矩阵测范数；没有QR或responses；目标直接max更新前和历史；导出移除来源占位数组 |
| Norm沿自身轨迹匹配 | 在本组train_phase得到ordinary后统一缩放所有A层；读取参考同轮标量，记录实际范数误差；不改B |
| B-only尾段 | 沿原run的round<=90边界；norm不从外部注入91—100轮A更新 |
| 观察不扰动训练 | 预测置于observational_model，恢复模型与随机状态；打乱用独立NumPy Generator；沿用原本地A隔离RNG |
| 续跑保持语义 | 目标规则及参考幅度写入sfra_config供原checkpoint配置比较；恢复历史及训练RNG；打乱固定顺序可重建 |
| 模型身份不混淆 | ordinary事件保留提案含义；提交模型另存commit/formal_lora；所有官方预测来自最终提交态 |
| 不因缺记录补训练 | 保存完整预测及模型，训练前检查旧参考恢复文件；自动原有模型前向评估及轻量结果打包 |

上述是接口、数据流、公式、边界和存档的静态审查结论。已执行六个Python文件AST语法解析和`git diff --check`，没有执行实验、冒烟、单元或GPU测试。真实耗时、显存和数值行为须由这四组正式运行产生。运行中保留非有限值、不能匹配范数等明确失败检查，不能把错误运行伪装成完成。

这四组覆盖约定问题，但不保证结果一定支持A，也不保证单seed能区分极小差异。若Full与简单控制接近，结论可以是“当前证据没显示复杂设计的额外价值”；这是实验答案，不默认追加模块或无限重跑。
