# 方法 B 路线实验：代码与运行说明

实现日期：2026-10-08。对应[实验协议](方法B_路线判别实验方案_20261008.md)。旧冻结训练文件未修改，新入口通过独立 worker 安装本进程的实验运行器。

## 1. 实现范围

| 组别 | 补充更新的自由度 |
|---|---|
| N | 完整 A，不做 B 补充更新 |
| P | 每个来源一个非负系数，所有模块共用，保留原始方向 |
| M | 每个来源、每个模块一个非负系数 |
| S | 每个来源、每个模块一个可正可负的系数 |
| C | 完整 C 可达的来源列空间 |
| F | 自由共享 B 残差，不依赖来源方向 |
| P-rot、C-rot | 各模块对全部来源施加共同左正交旋转 |
| O | 仅回放：旧 Adam/C 目标与正则，先复现旧 AB，再诊断 |

这里的 S 是符号自由度对照，**不是**已有论文表中的同频率 S 基线。

P/M/S/C/F 采用共同有效坐标、归一化梯度、空间投影和半径限制。C 通过列空间投影求解，再重建一组真实来源上的 C 矩阵核验；不能把这个新 C 与旧两步 Adam/C 的历史分数直接混算。P/M/S 系数文件使用 `R=sum_j alpha_j D_j` 的约定；写成平均形式时系数相应乘来源数，不改变可行集合。

完整训练固定 A=Full-CP、lambda=10、mu=1、protocol seed=42、rho=1、两步反馈、30/40/.../100 轮增强、fast-v2 f128 c4。半径由**当前普通 B 更新的有效范数**确定；F 不读取 AB 的幅度记录。未增加来源筛选、尾类保护或额外反馈客户端。

## 2. 入口与环境

入口：`scripts/run_cliplora_b_routes.py`。默认 `--stage plan`，显式 `--stage run` 才会启动 GPU 工作。所有命令从项目根目录执行，可在 PowerShell 或 Bash 中使用这些单行命令。

沿用项目的 CLIP 训练环境，另外需要 SciPy 的 `scipy.optimize.nnls`。本机验证环境为 Python 3.13、PyTorch 2.11 CPU、SciPy 1.16；这不是 CUDA 环境的兼容性验证。配置/输入预检不需要 CUDA；真实训练/回放需要项目完整依赖与 CUDA。

代码文件：

- `utils/b_route_math.py`：SVD 坐标、P/M 的 NNLS、S/C 正交投影、旋转来源、C 重建。
- `utils/cliplora_b_routes.py`：共同优化器、事件提交、诊断与成本。
- `utils/b_route_sampling.py`：按原图 ID 两折划分、诊断采样。
- `utils/b_route_replay.py`：加载普通 B 事件、分支隔离、O 等价性检查。
- `utils/cliplora_b_route_runtime.py`、`scripts/train_cliplora_b_routes.py`：独立运行器与 worker。
- `tools/sfra/b_routes.py`：输入合同、配对校验、回放/完整训练汇总。

## 3. 先运行固定快照回放

`SOURCE_RUN` 应指向服务器上的一条原始 A-only 或旧共享 AB 运行目录，其中直接有 `sfra_config.json`。不能指向多个 seed 的总目录，也不能仅有分析压缩包。

优先使用 A-only；若统一采用旧 AB，后期快照含旧 B 历史，报告中应写明。输入至少包括：

- `checkpoints/base_model.pt`。
- `events/r030_c000_main_normal_B/state.pt`、`event.json`，以及 60、90 轮对应文件。
- 原分区、见证样本、元数据、执行配置、启动命令和协议文件。
- `--include-legacy` 还要求每个所选事件的 `commit.pt`、`matrices.npz`、`calibration_manifest.json`、`probe_metrics.csv`，且来源必须是旧 .35/class-cyclic/.3/.001 共享 AB。

先查材料，不进入训练：

```text
python scripts/run_cliplora_b_routes.py --mode replay --stage plan --source-run SOURCE_RUN --output-root output/cifar100_LT/b_routes
python scripts/run_cliplora_b_routes.py --mode replay --stage preflight --source-run SOURCE_RUN --data-root DATA --output-root output/cifar100_LT/b_routes
```

材料齐全后执行：

```text
python scripts/run_cliplora_b_routes.py --mode replay --stage run --source-run SOURCE_RUN --data-root DATA --output-root output/cifar100_LT/b_routes
```

默认包括 N/P/M/S/C/F、30/60/90 轮、两折、rho=.5/1/2，每个非 N 分支保存第 2/8 步；此外运行 P-rot、C-rot 各三个抽取，固定 rho=1。旋转参数由种子/事件/模块/null_index 确定，两折共用。第 3–8 步循环使用原两批图片，不引入新独立样本。

若需要 O，在上述预检和运行命令中都加 `--include-legacy`。它先在原始反馈清单上核验 C、残差及前向损失，然后在两折的共同 fit 清单上运行旧优化器。稀疏折对现存尾/非尾组取均值、跳过空端；有完整组时已通过与旧优化器的 CPU 数值对齐测试。O 无新半径限制，单列为 `rho0/O`，这里的 0 是“无新半径规则”的标记。

对 source seed3407 只跑主半径时加 `--rhos 1`；回放种子从来源配置读取，不设置 `--seeds`。`--rounds 30` 可用于服务器首次单事件运行；之后可添加 60/90，已注册的同一事件配置必须保持一致。

可显式用 `--no-rotations`、`--skip-source-probe` 缩减首次工程检查；这样得到的结果不包含完整机制证据。修改某个事件的组别、半径列表等配置必须使用新输出根目录。

没有任何可用快照时，可补采一条新 N 轨迹到第 90 轮，再回放该目录：

```text
python scripts/run_cliplora_b_routes.py --stage run --arms N --seeds 42 --stop-after-round 90 --output-root output/cifar100_LT/b_routes_reference
```

其来源目录是 `output/cifar100_LT/b_routes_reference/runs/N/seed42`。要用于正式 N 对比，需随后用相同参数、删除停止参数并加 `--resume` 跑完 100 轮。

## 4. 完整训练的主比较

默认参考协议为已在项目中的 `references/full10_clientlt`，默认数据路径为 `DATA`。目录不同时显式传 `--reference-run`、`--data-root`，所有配对组保持一致。

```text
python scripts/run_cliplora_b_routes.py --stage plan --arms P C F --seeds 42
python scripts/run_cliplora_b_routes.py --stage preflight --arms P C F --seeds 42
python scripts/run_cliplora_b_routes.py --stage run --arms P C F --seeds 42
```

三个作业依次前台运行，分别写入 `output/cifar100_LT/b_routes/runs/P/seed42` 等目录。没有合格 A-only 结果时另跑 N；已有冻结 A-only 可以在汇总时传入。

锁定配置后需要配对重复时：

```text
python scripts/run_cliplora_b_routes.py --stage run --arms P C F --seeds 0 3407
```

只有依据 seed42 主指标决定继续研究来源路线后，才选择固定 W 的完整旋转对照。例如选择 P：

```text
python scripts/run_cliplora_b_routes.py --stage run --arms P-rot --seeds 42 0 3407
```

完整训练旋转固定 null_index=0，不从诊断的三个抽取中选择。脚本不会自动追加确认作业或替你选择 W。

## 5. 停止、续跑与来源保护

完整训练可显式加 `--stop-after-round 30` 在轮边界停止。继续时用原命令、加 `--resume`；不再提供停止参数就继续到第 100 轮。一次命令包含多组时，`--resume` 会检查并跳过完成组、恢复未完成组，也允许启动尚未创建的组。

回放续跑同样加 `--resume`：已完成分支核验输入身份及全部产物哈希后跳过；未完成分支从零残差重算。来源探测及辅助测量会重新生成，不恢复半步梯度。两个折与不同分支各自还原模型参数、模式和随机状态。

保存的合同包括新旧代码哈希和输入身份。变更代码、数据协议或已注册作业配置时会拒绝原地续跑。输出与来源目录必须分开；写入只发生在输出目录。完整训练分支的 `commit.pt` 只保存 LoRA，避免每个事件重复存完整 CLIP。

## 6. 汇总、打包与判读

```text
python scripts/run_cliplora_b_routes.py --stage status
python scripts/run_cliplora_b_routes.py --stage summary --baseline-run A_ONLY_SEED42 --baseline-run A_ONLY_SEED0 --baseline-run A_ONLY_SEED3407
python scripts/run_cliplora_b_routes.py --stage pack --baseline-run A_ONLY_SEED42 --baseline-run A_ONLY_SEED0 --baseline-run A_ONLY_SEED3407
```

`--baseline-run` 可按已有结果重复提供，也可完全省略。运行 N 的新目录会自动收集。旧 A-only 必须有可核验的冻结代码回执才能组成配对；没有回执的结果仅展示。需要正式补齐 N 时可用同一套新入口重跑。

主要输出位于 `<output-root>/analysis`：

| 文件 | 用途 |
|---|---|
| `per_run.csv`、`paired.csv` | 每 seed 正式 last20/末轮指标及配对差 |
| `paired_summary.csv`、`paired_per_class.csv` | 开发/重复的描述性统计、全部类别的变化 |
| `status.csv`、`pair_audit.csv` | 不完整、无效结果及配对失败原因 |
| `decision.md` | 按预设 .10 个百分点参考线列出证据是否齐全；不宣称统计等效 |
| `event_branches.csv`、`replay_paired.csv` | 同状态各步/各半径/两折指标及旋转均值对照 |
| `solver_trace.csv`、`objective_trace.csv` | 求解器每步记录和固定两批目标 |
| `source_geometry.csv`、`directions.csv`、`coefficients.csv` | 秩、投影捕获率、C 相对 P/S 剩余量、与 F 的余弦、来源系数 |
| `source_probe.csv` | 原始 .1 扰动与匹配有效范数扰动，fit/诊断分列 |
| `costs.csv`、`replay_status.csv` | 回放成本与完整性状态 |

事件目录还保存逐样本四种正确性变化、原图 ID 两折清单、第 2/8 步残差与 C 重建。诊断 margin 使用 raw-logit 的正确类减最大竞争类；来源探测沿用旧 LA 改善定义。

`primary_two_steps_*` 是前两步成本，`diagnostic_extra_steps_*` 是额外六步成本；`diagnostic_forward_images` 单列只读测量。优化计时、诊断前向计时和总时间分别保存；它们还可能包含服务器几何计算、日志 I/O，不能等同于真实分布式网络耗时。峰值显存在 CUDA 上记录，CPU 测试不伪造显存数值。通信是模拟的 FP32 密集消息预算，P/C 也上传共同残差梯度，不按小 C 参数数虚报成本。

分析包包含标量/配置/审计材料，省略 `.pt` 权重。便携汇总核验标量产物，回放续跑额外核验权重文件；分析包不能用于恢复训练或重放。

## 8. 实验数量与多 GPU 拆分

先做 seed42 的 3 个事件回放，再做 P/C/F 的 3 条完整训练。已有合格 N 时不重跑 N。

默认回放实际生成 144 个分支记录：90 条 P/M/S/C/F 短优化分支、36 条随机旋转短优化分支、18 条 N 零更新评估。126 条优化分支各执行 8 步，共 1008 个同步反馈步，包含第 2 步结果；此外还有来源探测与只读诊断。这些不是 144 条完整训练。每个事件承载 48 个分支记录，其中 42 条优化、6 条 N 评估。启用 O 另加 6 条两步 fit 分支，以及 3 次旧事件复现。

后续若决定继续，seed0/3407 的 P/C/F 新增 6 条完整训练，主比较合计 9 条；固定胜出路线 W 的旋转对照在三个 seed 上再加 3 条，共 12 条。N 缺哪个 seed 就补哪个；若只缺 seed0 N，则共 13 条。缺失的参考轨迹和 N 可以共用同一条新运行，避免重复计数。M/S 没有默认完整训练任务。

推荐一个进程只看到一张 GPU。当前单个启动命令会顺序执行列出的作业，不自动把 `--arms P C F` 分配到三张卡。可以在三个终端分别启动以下 Linux/Bash 命令：

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/run_cliplora_b_routes.py --stage run --arms P --seeds 42 --output-root output/cifar100_LT/b_routes
CUDA_VISIBLE_DEVICES=1 python scripts/run_cliplora_b_routes.py --stage run --arms C --seeds 42 --output-root output/cifar100_LT/b_routes
CUDA_VISIBLE_DEVICES=2 python scripts/run_cliplora_b_routes.py --stage run --arms F --seeds 42 --output-root output/cifar100_LT/b_routes
```

PowerShell 则在各自终端先设置对应的环境变量，再启动相同 Python 命令。例如 GPU0：

```powershell
$env:CUDA_VISIBLE_DEVICES = '0'
python scripts/run_cliplora_b_routes.py --stage run --arms P --seeds 42 --output-root output/cifar100_LT/b_routes
```

回放按事件拆分，保持来源、组别和半径等其余配置一致：

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/run_cliplora_b_routes.py --mode replay --stage run --source-run SOURCE_RUN --rounds 30 --output-root output/cifar100_LT/b_routes
CUDA_VISIBLE_DEVICES=1 python scripts/run_cliplora_b_routes.py --mode replay --stage run --source-run SOURCE_RUN --rounds 60 --output-root output/cifar100_LT/b_routes
CUDA_VISIBLE_DEVICES=2 python scripts/run_cliplora_b_routes.py --mode replay --stage run --source-run SOURCE_RUN --rounds 90 --output-root output/cifar100_LT/b_routes
```

同一事件目前由一个 worker 管理两折和全部路线，不把同一事件分给多个进程。普通训练的连续轮次也由同一作业执行；完整训练按方法/seed 拆分。

启动器已对公共 `route_plan.json` 的读取、合并、写入加锁；预检记录分别保存在 `preflights/`，根目录 `preflight.json` 仅代表最近一次预检；每个训练/事件目录另有执行锁。因此不同任务可以共用上述输出根目录，全部完成后运行一次 summary/pack 即可。

同一台机器上保持配对作业的代码、数据、参数、精度和软件环境一致。若要改变 `--num-workers`，在整组新作业开始前统一确定，不能为已注册作业临时改值。并发时 CPU、内存与磁盘由多个进程共享，实际墙钟加速需实测；三条完整训练由顺序耗时之和变为并发耗时的最大值，仅在资源充足时接近三倍吞吐。多 GPU 不降低总训练工作量。

本次并发补丁会改变新入口的合同哈希。已经注册或正在运行的旧版本任务应保留原代码完成；新启动的并发批次统一使用本版代码。

## 9. 初始化报 `AssertionError: probe_manifest_sha256`

已复现的原因是参考 CSV 的换行转换：`references/full10_clientlt/protocol/probe_manifest.csv` 的历史元数据记录 CRLF 版本的 SHA256（`8a43f25c...`），Git 存储的是 LF 版本（`0bfa0a2d...`）。Linux 检出后逐行内容和图片 ID 相同，但原始字节哈希不同，旧启动器直接复制文件，导致初始化中的严格身份校验失败。

修复位于 `tools/sfra/b_routes.py`、`scripts/run_cliplora_b_routes.py`、`scripts/train_cliplora_b_routes.py`。预检只读验证原始字节及 LF/CRLF 两种候选，必须有一种**精确匹配原记录的 SHA256**；启动时只恢复新输出目录中的副本。参考原文件、元数据中的哈希、样本身份和训练算法保持原值。如果实际行内容、编码等发生变化且两种换行均不匹配，预检直接拒绝，不启动 GPU worker。worker 也在导入训练模型前复核最终副本。

修复动作记录在每个作业的 `route_spec.json` 和 `protocol/probe_manifest_identity.json`，并出现在 `preflight.json` 的作业列表中。LF→CRLF 恢复时，启动日志会出现：

```text
Probe manifest: restored CRLF line endings in output copy; original SHA256 verified.
```

用户所贴的 F 日志在运行器初始化时失败，尚未进入正式训练，没有可恢复的轮边界检查点。把最新实验代码同步到服务器后，首批仍只做 seed42，用一个新输出根目录保留旧失败日志并重新启动：

```bash
python scripts/run_cliplora_b_routes.py --stage preflight --arms P C F --seeds 42 --output-root output/cifar100_LT/b_routes_seed42_fixed
python scripts/run_cliplora_b_routes.py --stage run --arms F --seeds 42 --output-root output/cifar100_LT/b_routes_seed42_fixed
```

若 P/C 也因同一错误失败，在各自已分配的 GPU 会话用同一输出根目录，把 `--arms F` 分别改成 `--arms P`、`--arms C`。三个作业使用同一版代码。此次是重新启动，命令不加 `--resume`；新输出根目录避免与失败任务保存的旧代码合同冲突。

本地测试能复现和修复所报告的文件身份问题，但不代替服务器上的真实 CUDA 初始化与训练检查。
