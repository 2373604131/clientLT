# 方法 B 重审：面向尾部客户端的尾类知识迁移

状态：历史审核稿，已被用户随后固定的“缺标签来源增强尾类正向支持”目标修订。当前已实现的规则与命令见 [方法 B 定向迁移](cliplora_b_directed.md)。下文中的“允许来源持有目标类、全局最多三个来源、非零 C 初始化”不再采用；保留本稿用于追溯审核依据。

## 目标与边界

B 的直接目标是：利用尾部客户端之外的有益更新，提高尾部客户端所持尾类的学习能力。非尾类训练损失、Overall、非尾损害惩罚不作为 B 的优化或 donor 选择依据。A 的既定更新继续执行。

所有模块仍作用于同一个共享模型，因此目标上的职责划分不等于参数效果完全隔离，也不能预先保证 A 会补偿 B 对其他类别的影响。完整结果照常记录各组精度，但 B 的主要效果以全局测试集的固定 Tail20 宏平均衡量，不改变测试类别或评估集。

## 已确认的三个问题

### 1. 接收端范围与新目标不一致

`utils/cliplora_b_transfer.py` 当前通过 `self.recipients = sorted(self.probes)` 选择所有持有任一尾类的客户端，当前数据中共有 22 个。

Client-LT 协议按客户端组指定的尾部客户端是 27、28、29，分别持有 42、37、40 张尾类训练图片，共 119 张，覆盖全部 20 个尾类。全体客户端共有 156 张尾类图片，另外 37 张分布在其他 19 个客户端。

现有 C 损失对 22 个反馈端等权，再做尾/非尾组加权。三个主要尾部客户端都包含非尾样本，所以 w=0.5 时，它们的尾类项合计系数仅为 `(3/22)*0.5 = 0.06818`。这表示分类校准损失中的系数份额，不表示实际梯度范数占比；但它明确说明当前目标没有集中到新的服务对象。w=0.35 和 0.2 会进一步降低这一份额。

修订：接收端从划分协议读取尾部客户端组；在当前运行中就是 27、28、29。不能永久硬编码这些 ID，也不能在其他划分上未经定义就套用这一客户端范围。

### 2. donor 的接纳与使用脱节

当前共享 B 对每个接收端执行 `accepted |= gain > 0`，即任一 eligible 尾类受益就接纳该 donor，然后 `pool.update(donors)` 取并集。C 随后在整个并集上校准。

现有日志还显示：只保留 27、28、29 的目标类、只考察 0–26 的外部来源时，第 30、60、90 轮的正收益并集仍都是全部 27 个外部客户端。即使对每个“接收端—类别”仅取正收益 Top-3，合并后也分别是 24、25、24 个来源。因此，“逐类 Top-K 后再无条件取并集”依然不能解决问题。

修订：为最终的共享迁移项直接选择一个有限 donor 集合，不再用局部合格关系的并集确定它。

### 3. “缺少目标类”不等于“能够帮助目标类”

现有代码只在 donor 缺失的目标类上记录收益。这个约束用于研究跨类别迁移，但它排除了持有该类、也可能有帮助的来源。

按当前“优先提高尾类学习”的目标，默认允许外部 donor 有或没有对应尾类，按真实目标收益筛选；保留类别存在标记，后续表述据此区分同类与跨类来源。这样做会改变原来的候选协议，必须用新的运行配置，不能把已有结果改名当成新方法结果。

## 修订算法

### 一、固定服务对象与统一目标

令 K_T 为协议指定的尾部客户端组，T 为该组实际持有的全局尾类。当前 K_T={27,28,29}，T={80,...,99}。

使用这些客户端的尾类训练数据。对类别 c，先合并该类在 K_T 中的损失和样本数，再得到该类平均损失 L_c；最后对类别等权：

`L_tail(B) = (1 / |T|) * sum_c L_c(B)`。

各客户端只需上传对应的类别统计/梯度，不需要把图片传给服务器。由于当前只有 119 张目标图片，首版可直接使用固定的完整目标尾类训练池，按客户端分批计算；无需保留原来每步“16 尾+16 非尾”的采样结构。每个类别先按实际样本数归一化，再做类别宏平均，避免把客户端等权误当作类别等权。

损失沿用全局训练先验下的 LA 和全部 100 类 logits。只使用尾类标签的训练图片，不等于把分类任务改成 20 类分类。不增加非尾项，也不继续搜索 w。

### 二、在实际共享模型上选择最终 donor 集合

仍先完成普通本地 B 训练及 FedAvg，得到 B_bar，缓存原始 donor 更新 ΔB_j。迁移期间 A、B_bar 和原始 ΔB_j 固定。

候选池默认是参与当前轮次且位于 K_T 之外的客户端；当前即 0–26。选择依据是同一个 L_tail，保留各类别的正负收益，不使用“任一类为正即接纳”的规则。

建议首版固定最多 K=3 个来源。这个值是控制来源数量和筛选预算的工程起点，不宣称最优，不再增加一组 K 扫描。为避免重复选择作用相近的来源，可采用条件增益选择：

1. 从 S=空集、R_S=0 开始。
2. 对尚未选择的 donor j，在 `B_bar + R_S` 上注入 `alpha * ΔB_j`，alpha 先沿用 0.1。
3. 计算每类收益 `g_jc = L_c(B_bar+R_S) - L_c(B_bar+R_S+alpha*ΔB_j)`，再对所有目标尾类取平均 `s_j`。负收益必须进入平均，不能只保留正部。
4. 选择 `s_j` 最大且确有正收益的来源，更新 `R_S += alpha*ΔB_j`，重新计算其余来源的条件增益。若最大收益未超过数值容差（首版可用 1e-6），停止；否则最多选 3 个。
5. 并列时按客户端 ID 固定顺序打破平局；无合格 donor 时，本次额外迁移为零。

筛选用固定训练侧目标池，是 B 算法自身的优化步骤。最多三轮候选搜索增加前向成本，需如实记录；不声称计算量与旧筛选完全相同。它不需要另开第 30/60/90 轮离线检测实验。

这种筛选定义的是“对目标尾类集合有正向平均条件收益的来源”，不保证某个 donor 对每个尾类都受益。共享模型中的不同尾类仍可能存在取舍。如果未来需要“每个类别独立路由到专属 donor”，那将是另一种模型结构，不能把本设计包装成已经实现该能力。

### 三、只在选中来源上优化共享 C

最终的额外迁移项为：

`R(C) = (1 / |S|) * sum_{j in S} ΔB_j @ C_j`。

未选中的客户端不创建 C 块、不接收这部分梯度、不进入重建。普通 FedAvg 仍然使用原协议的全部客户端更新；“筛掉来源”只针对额外迁移项，不能宣称其普通训练贡献也被移除了。

保留每 donor、每 LoRA 模块一个完整的小矩阵 C，优化 `L_tail(B_bar + R(C)) + lambda_C * ||C||²`。该正则用于控制小样本下的变换规模，不负责保护非尾类。先保留原有 C 学习率和两步更新，不同时扩大超参数搜索。

为使 C 校准从筛选验证过的组合开始，可令每个选中块 `C_j = |S| * alpha * I`；此时初始 R(C) 恰好等于条件筛选结束的 R_S。这个非零初始化与旧版不同，必须记录在配置和方法中，不能默认为沿用旧零初始化。之后 C 的优化仍可能改变组合行为，筛选阶段的正收益不构成最终测试收益保证。

优化始终在实际最终共享模型 `B_bar + R(C)` 上计算同一尾类目标。迁移一次并回 B，不再乘尾部客户端的数据量比例，不再次执行 FedAvg，以免这一尾类补充被小客户端的样本权重再次削弱。随后按既定顺序执行 A。

## 对旧设计的处置

- 不再继续非尾轮换采样和 w 扫描作为 B 的主线。
- 不沿用旧 E00/E10/E01/E11 作为当前必做计划；它们没有修复新的接收端范围与最终 donor 来源约束。
- 不把“删除 donor 筛选”作为最终方案。保留筛选，并让它直接限制最终可使用的外部更新。
- 不把只更改 `--transfer-tail-weight 1` 当成实现：现有 CLI 要求 0<w<1，且改变这个数值不会修正接收端、类别归一化或 donor 并集问题。
- 原结果保留为历史版本，训练脚本与现有断点本次审核没有修改。

## 方法主张与最低判断依据

建议表述：方法 B 以尾部客户端的尾类反馈为依据，从外部客户端选择少量具有互补收益的更新，并通过共享低秩变换将其补充到共享模型，增强尾类学习。

“具有互补收益”目前是条件筛选的设计目标，只有训练侧条件收益得到保证；测试泛化还没有验证。已有 donor_scores.csv 省略了 donor 持有目标类时的反馈，也来自旧轨迹，因此不能从现有文件宣布新方法的最优 donor ID。每次迁移应根据当前状态重新选，不能将某个旧轮次的 ID 固定到整个训练。

方法效果用完整训练的 Tail20 最后 20 轮平均精度判断。若论文要归因于 donor 筛选，必须有一个同样的尾类目标、接收端、C 预算下使用全部外部来源的对照；只比较旧 B 与新 B，不能把接收端和目标改变的收益都算给筛选。这里不要求再做逐轮离线诊断，也不承诺新的尾类提升幅度。
