# 旧版 B 与故事主线的一致性审查

日期：2026-09-29。范围：旧共享 B 及三组 shared-tradeoff；结合截至本次对话已收紧的 B 目标。不修改训练代码，不启动训练。

采用 `tech-paper-template` 的逻辑检查。结论是：旧版的反馈驱动共享 C 重组，可以服务于“功能保持之外补充尾类学习支持”的总体故事；它不能原样充当“仅面向指定尾部客户端尾类、按类定向利用缺标签外部来源”的完整实现。C 可以保留，筛选关系和训练目标需要准确解释或继续改进。

## 1. 定位与适用边界

就 B 而言，按技术方法模块审查：其贡献需要落在如何组织和利用更新，不能仅以 Client-LT 场景或组件命名代替机制。这里不重新决定整篇论文定位，也不声称 Client-LT 或 C 已具备经穷尽检索确认的新颖性。

主线原文见[论文故事主线第七部分](论文故事主线_20260926.md)。后续用户进一步固定的 B 职责是：维护之外增强正向支持；目标为协议尾部客户端所含尾类；来源应来自目标组之外并缺少对应目标类标签；Overall 不是 B 的优化任务。

## 3. 旧版与具体主张的对照

| 主张 | 判断 | 理由 |
|---|---|---|
| A 维护已有功能，B 补充学习支持 | 相容 | 旧 B 在普通聚合之后，用反馈重新组合客户端更新，形成额外共享 B 更新。 |
| 缺少目标标签的来源仍可能帮助尾类 | 可作动机 | 探测记录支持训练样本上的正向损失响应；它不等于最终收益的来源归因。 |
| 旧 B 按目标类筛选并定向使用缺标签来源 | 未落实 | 各端认可关系取并集，最终每次仍用全部30个客户端；后续 C 没有按类别保留这些关系。 |
| 旧 B 仅以指定尾部客户端中的尾类为反馈对象 | 与实际不符 | 反馈来自22个持有任一尾类的客户端，且 C 使用尾类与非尾类混合目标。 |
| C 已提取出语义上纯净、有益且互不干扰的知识 | 无依据 | C 是更新变换参数，其代数形式和平均损失下降都不提供这种语义保证。 |
| 旧 B 的收益证明无目标标签来源提高了测试准确率 | 归因不足 | 全池同时包含有/无相应标签的来源及目标组本身，还缺少匹配控制。 |

### 接收端与标签缺失必须分开定义

旧版的“尾类持有客户端”共22个；协议的“尾部客户端组”是27、28、29。两者不能都简称尾类客户端而不加定义。

某 donor 因为帮助类别 c 且缺少 c 而入池，不代表它对其他类别 d 也缺标签或有帮助。由于全池最终包含30个客户端，它也包含协议目标组及对应类别的持有者。因此旧版最终增益不能归为“完全来自目标组外的缺标签迁移”。

## 4. 方法设计需要修正或补证的地方

### 4.1 探测与最终使用脱节

旧代码只要 donor 对任一 eligible 尾类的 LA 收益为正就接纳，然后取并集。进入 C 校准后使用 donor ID 和更新，不再使用原来的逐类认可关系及其收益大小。当前各事件并集都为30，筛选没有改变最终候选集合。

这说明筛选的必要性和作用没有成立；不说明 C 的联合校准无效。C 可分别变换不同 donor 的更新，仍可能获得收益。若保留定向选源主张，目标类与来源之间的关系需要继续参与实际目标或组合规则。

### 4.2 显式优化目标与后来固定的职责不一致

旧版混合客户端的损失为 `w * mean(LA_tail) + (1-w) * mean(LA_non_tail)`，再对22个客户端等权。只有尾类的客户端另按纯尾损失处理。

因此它是混合分类反馈下的共享更新校准，不能把非尾损失写成“只记录的监控指标”或“没有参与 B”。非尾反馈可能有助于尾类边界，但这是候选解释；若今后采用辅助反馈，应明确其用途和范围，不能静默替代用户已固定的尾类目标。

客户端等权也不等于尾类等权。协议目标组三个客户端的尾类损失在混合目标中的显式系数合计为 `(3/22)*w`；这不是梯度范数占比，更不能独自解释测试结果。

### 4.3 单独探测与最终提交不是同一个方向

探测为 `B_bar + 0.1 * ΔB_j`，实际提交为 `B_bar + mean_j(ΔB_j @ C_j)`。各 donor 分别变换后，还需相加并通过非线性模型产生响应。单独为正不能直接推成最终为正。

后续校准确实在同一个共享候选上联合优化，这一点值得保留。但其平均分类目标允许类别取舍，未要求实现原来筛选时的各类正响应。

### 4.4 C 的独立价值与最终增益来源尚未分开

旧版 Tail20 末20轮均值相对 A-only 提高0.1525个百分点，轮换版本提高0.1750—0.2225个百分点；均为 seed42。现有结果提供保留该路线的理由，不能分别证明：筛选有效、C 必需、无标签来源贡献独立，或优于匹配预算下的额外训练。

这属于必要性与归因缺口，不是已经发现实现错误。也没有依据把 lr=0.3、两步优化或使用 C 本身认定为 bug。

### 4.5 “知识补充”的含义需要准确

这些客户端的普通更新已经参与 FedAvg。B 使用已产生的更新和额外目标反馈，改变其作用方式；没有新增客户端或有标签样本。应解释为“进一步利用已有跨客户端更新中的有益信息”，避免声称扩大了实际数据来源数量。

## 5. 写作中的具体调整

| 容易写过头的表述 | 对旧版更准确的表述 |
|---|---|
| 为每个尾类筛选最有帮助的无标签 donor，并只迁移它们的知识 | 对缺类来源进行局部探测形成候选并集，再由共享 C 联合校准；当前逐类认可关系未保留到校准中。 |
| B 只针对尾部客户端的尾类优化 | 当前旧版使用所有尾类持有客户端的混合分类反馈；若坚持严格范围，需要修改算法。 |
| B 扩大了尾类的数据或实际来源数量 | B 尝试提高已有客户端更新对尾类的利用效率。 |
| C 消除负迁移或提取纯净通用知识 | C 学习各来源更新的变换，通过共同候选模型上的反馈控制组合。 |
| 正探测收益证明缺标签来源带来尾类测试提升 | 正探测收益支持迁移动机，最终来源贡献仍需独立归因。 |
| B 已进一步解决尾类遗忘 | B 在现有运行中小幅提高尾类平均测试水平；独立保持收益尚未得到充分确认。 |

“定向”若只表示训练目标偏向尾类，需要明说；若表示逐类限定来源，必须在实现中保留这种关系。不能在两种含义之间切换。

## 6. 四项一致性检查

| 检查 | 结果 |
|---|---|
| 局限→核心思路 | 通过：维护已有能力与利用现有外部更新，回应保持和学习支持两个问题。 |
| 核心思路→挑战 | 通过：继续适配时维护功能、将局部响应转成共享收益，均为自然产生的挑战。 |
| 挑战→方法 | 严格主张下未通过：旧版没有实现后来指定的反馈范围和逐类缺标签来源使用。 |
| 方法→贡献 | 严格主张下未通过：旧 B 的小幅测试增益不足以证明定向筛选或缺标签迁移的独立贡献。 |

按本技能的逻辑断点标准，以上为2项 CRITICAL：范围/机制对应和贡献归因。它们不是2个已证实的代码 bug，也不是说整个论文故事不成立。其他主要缺口是 C 必要性和收益稳定性，属于证据问题。

## 7. 方法段落的建议骨架与处理顺序

方法总述：以功能反馈组织共享模型中的保持与学习支持。

1. 功能保持 A：交代当前与历史功能目标、来源信息，以及适配与保持的协调。
2. 反馈驱动的更新重组 B：先明确定义目标端、目标类和来源资格，再说明 C 的组合形式、共同候选上的目标与一次提交。
3. 效果解释：区分局部响应、组合优化、尾类测试增益和后续保持，避免把四者写成已经成立的因果链。

优先保留共享 C、普通聚合后的联合校准和单次提交；不因新版结果直接取消 C。保留“尾类支持增强”的故事目标，同时修复来源关系在使用阶段的断裂，并明示实际反馈范围。取消 C 的直接 B 蒸馏降为备选；正响应监督也可以用于优化由 C 生成的共享候选。

若论文直接采用未经修改的旧版，应将 B 定位为反馈驱动的辅助重组，并收紧相应主张；若坚持现有严格的定向缺标签迁移目标，旧版只能作为有正收益的参考结构，不能原样改名为最终方法。

下一步是解决上述机制与主张的对应关系；当前不进入 Introduction 成稿，也不新增逐轮重放或大范围实验。
