## 2. 问题1：修正到底伤了谁？

### 2.1 先利用现有记录，不重新训练

已有数据：sfra_rounds/rXXX/tokens.npz保存了普通提案和正式提交后的逐客户端—类别LA损失、功能margin、来源响应、权重和历史。private_witness_manifest.json提供类别对应，partition_summary.json提供实际记录的训练类频数。

先对第1–90轮重汇总，预先分为1–30、31–60、61–90三个窗口。第91–100轮没有A修正，单独列为B-only阶段，不混进修正效果均值。

每个窗口输出一张表：

| 看什么 | 具体记录 | 回答什么 |
|---|---|---|
| 分类损害 | 提交后LA减普通提案LA；逐类均值及损失上升的类别数 | 哪些类别受损，是否集中在Medium |
| 正常学习与修正 | 更新A之前→普通提案→Full-CP的margin变化 | 修正是撤销了正常学习收益，还是仍有净收益 |
| 组间掩盖 | Many35、Medium35、Few30分别统计；另列Tail20 | 总体平均是否掩盖某组下降 |
| CP工作情况 | 最终LA增量、第2/3步激活、两项梯度夹角 | CP是否生效、是否仍有残余损害 |

两种平均同时保留：按原样本量加权，用于对应现有CP目标；先按类平均，再组内平均，用于避免大类掩盖小类。同一类内部如何合并客户端单位也必须写明，沿用现有诊断的单位等权口径，并另报样本加权口径。

LA是训练损失，margin是分数差，两者都不能冒充准确率。现有token文件是单位/视图平均值，不能由它反推出每张图片是否预测正确。

**已有线索：** 第61–90轮，Full-CP μ1对Medium35的类均衡LA平均增加约0.001287，对Tail20平均减少约0.002712。这支持检查修正步骤，但不能独自证明测试集Medium下降全部由该步骤或CP粒度造成。无CP Full与Full-CP是不同长期轨迹，也不能当作同状态CP因果对照。

### 2.2 新实验只增加同状态评估

在问题2的三个候选上，顺带记录逐类损失、margin和真实预测对错。优先用固定的训练见证诊断目标行为；未进入反馈的训练图片可检查是否只对见证有效，但它们仍是训练数据。独立验证/测试才评价训练外表现，结果不得反向决定历史目标、缩放系数或选取哪个中间候选。

必要的前向状态是：A更新前、普通提案后、Full-CP后、缩步后。“A更新前”只是公共参照，不是第四条训练分支。

**问题1的完成标准：** 能说清楚哪些类被削弱、削弱发生在普通学习还是修正阶段、总体平均是否掩盖了分组代价。先完成定位；本轮不以“已经修复Medium下降”为验收条件。

为回答“CP本身究竟帮了多少”，当前执行版已纳入两个起点各一次μ=0的三步修正，与μ=1比较。这是同状态单次事件探针，不增加整条五轮或100轮分支，也不搜索多个μ。其差异衡量当前起点上CP的局部作用，不能把长期轨迹的全部分类变化归因给CP单独一项。

## 3. 问题2：是不是少更新一点就够了？

### 3.1 单次比较：同一起点，三种提交

建议固定检查第61、81轮A事件，对应已完成第60、80轮的两个起点。不根据Tail峰值挑轮次；若文件缺失，先按状态可恢复性登记替代轮次，不查看候选表现后再改轮次。

本轮普通B聚合后，固定共同模型、客户端更新、普通A提案、见证、来源响应、历史和随机状态。

| 候选 | 提交方式 | 用途 |
|---|---|---|
| 普通更新 | 直接提交普通A提案 | 看未修正的学习与损害 |
| Full-CP | 提交冻结规范的第三步结果 | 当前方法参照 |
| 等步幅普通更新 | 保留普通提案的方向，仅统一缩放增量 | 隔离步幅与方向的差别 |

匹配的是更新前后有效LoRA矩阵变化的范数，所有层合并计算；不是只匹配A参数范数，也不是把本地学习率乘0.377。对于本轮固定B，有效变化为ΔW=sBΔA。用Full-CP的有效更新范数除以普通提案的有效更新范数，得到正标量α，再提交A起点加α倍普通增量。

只用一个标量缩放所有层，不做逐层或逐类缩放；后者会加入新的方向分配规则。逐事件记录α、匹配误差、A参数方向余弦和有效ΔW方向余弦。如果α大于1，如实称为放大而不是缩小，不能偷偷截断为1。普通有效范数接近零时标记不可匹配，不用极大系数强行匹配，也不隐藏该事件。

如果权重和普通提案已经保存，这一步主要是构造候选和前向评估，不需要重新跑100轮；Full-CP重算时须先验证能复现原提交结果。

### 3.2 短程比较：两个起点，各五轮

从第60、80轮完成状态分别分出上述三条分支，运行61–65、81–85轮。三个分支采用相同客户端日程、样本、训练epoch、每轮随机种子和评估规则。后续B照常训练；它会随着分支状态自然分叉，不能每轮强行拷贝另一分支的B。

为减少诊断成本，采用以下明确的“参考幅度匹配”协议：

1. Full-CP分支先运行五轮，保存每轮实际有效A更新范数。序列只来自训练更新，不使用测试表现。
2. 普通更新分支按普通提案运行。
3. 匹配分支在自己的当前模型上计算普通提案，用一个正标量将本轮有效更新范数匹配到Full-CP同轮记录值，随后只提交这个缩放后的普通增量。

匹配分支借用了Full-CP的幅度序列，必须明确标记为诊断控制，不能宣传成不依赖Full-CP的廉价新算法。两分支在第一轮之后状态会不同，因此它回答的是固定起点后的短程策略差异，不是五次完全相同状态下的局部因果比较。单次同状态比较与短程比较分开报告。

Full-CP历史只由自己的正式提交状态更新。其他分支不使用Full-CP的后续历史或方向。评估过程保持随机状态隔离，不能因为多做一次前向而改变训练随机性。

**训练规模上限：2个起点×3个分支×5轮=30个分支训练轮。** 这是一个seed的开发诊断，不是30次独立重复。若旧Full-CP对应片段通过状态、实现和随机性核对，可复用；否则三个分支统一重放。准备/恢复起点的工作不包含在这30轮里，必须另报，不能在缺少模型状态时仍声称总成本只有30轮。

只预先固定五轮，不因为结果不理想就不断延长。报告五轮各轮数值、五轮平均、起点到第五轮变化，两个起点分别展示，不根据最佳点选结果。

### 3.3 判断规则

- Full-CP在相近Overall/Medium代价下，Tail或已学会样本的保持优于匹配普通方向：支持完整修正方向具有局部/短程价值。
- 两者接近：当前诊断没有显示复杂方向的额外收益，不把“没有显著差异”写成已经证明等效。
- Full-CP只在训练见证上更好：尚无反馈外或泛化证据，应先查见证局限。
- Full-CP的Tail更好、Medium也更差：仍是取舍；应如实报告，不能仅挑Tail宣布机制胜出。
- 简单匹配方向整体更好：先重新审视A修正，不用不断增加组件来救预设结论。

这套短程实验不能排除所有独立小学习率/缩步策略，也不能代替从初始化开始的完整轨迹比较。最终需要时，再用训练侧预先固定的缩步配置跑完整对照；不能直接把后期平均37.7%当成全程最优系数。

## 4. 哪些记录可以顺带加，哪些会增加新训练？

### 顺带记录，基本不增加训练分支

1. **逐样本预测。** 保存固定评估集的样本ID、标签、预测与margin。只用于评价，不传回历史目标或修正过程。
2. **旧能力与新学会能力。** 若能恢复初始模型及分支前连续三个模型，在分支前固定两个队列：初始正确且分支前连续三轮正确；初始错误、分支前连续三轮正确。跟踪各分支五轮后的正确保留率、正确转错数，以及原先错误转对数，报告各队列大小。后一队列为训练后学会提供更直接证据；不能把见证margin历史当作这份逐样本证据。没有这些模型/预测时，此项只能补今后的记录，不能由逐类准确率反推。
3. **来源数量与支持强弱分开。** 保存有效来源数、未加权正向响应总量、样本加权正向量及负向量，描述Full-CP与普通/缩步候选改变了哪些功能。它是局部描述与关联，不能由Full-CP已经干预过的轨迹证明“来源少必然更脆弱”。
4. **阶段变化。** 用轮初→普通B后→普通A后→修正后，分开记录功能变化。只有实际采集的损失才报告；现有文件未保存的阶段损失不能估算成已观测值。
5. **成本。** 记录正常训练、来源测量、三步修正和额外诊断的耗时、前后向样本数、通信估算。评估开销与算法开销分开；复用前向和嵌套计时不能重复相加。模拟通信字节数不是真实网络延迟。

### 来源探针：后续备选，本轮不执行

如果希望本轮直接触及意见中“来源优先级有没有用”，在第61、81轮共同普通提案上，再生成Flat-CP候选：保持同一目标、历史、CP和修正步骤，只将有效功能单位权重设为均匀。

这会增加两次三步修正事件，涉及反向和反馈，不能称为零成本；不需要为它另开100轮或默认增加五轮分支。记录它的有效步幅，以免把幅度变化误当成来源分配效果。

它能提供来源优先级的局部增量证据，但不会移除构造当前目标的来源响应，也没有控制所有幅度差异；更不能代替打乱来源对应、普通功能保持或同版历史消融。现有Full-CP相对Flat-CP的Tail +0.88点是单seed、不同执行路径的初步结果，仍需保留这些限定。

## 5. 审稿意见：现在能回答到哪一步

意见的主要风格偏“具体、建设性、看重对照”，中等置信：附件明确提出了可执行比较，并保留“主线值得继续”的判断。应逐项给出已有事实和实际可补的证据，不使用模拟评分或技能中的群体统计推算录用概率。

| 意见 | 目前处理 | 本轮能提供什么 | 不能提前说什么 |

| 创新性要具体，区别于已有保持/LoRA方法 | 现在可收紧贡献表述；相关论文原文与实现差异需另行核对 | 说明作用对象、当前/历史目标和来源优先级的准确行为 | 未核对文献就宣称别人没有做过，或用本轮两个实验证明新颖性 |

| CP有没有用、是否保证各类不下降 | 定义和已有取舍现在可回答 | 问题1查损害；当前执行版的两次μ=0单步探针检查CP局部贡献 | CP提供硬保证；负梯度夹角意味着永远无法兼顾 |
| B是否超出普通FedAvg、筛选/适配/额外训练哪个有效 | 等B定义稳定后单独设计 | 当前只准确描述已有证据与缺口 | A实验顺带证明B必要或抗遗忘；把正向响应称为已解耦知识 |
| A/B是否天然存储不同知识，遗忘是否主要来自A | 现在可澄清它们是交替优化因子 | 顺带阶段记录显示哪里出现回落、哪里被修复 | 在A阶段修复有效就意味着损害一定由A造成 |
| 反馈在哪里算、服务器收什么、多少同步、成本多大 | 实现路径可现在说明，精确成本需审计 | 利用现有日志并补当次计时和载荷；三次修正各需反馈，另有来源/最终评估阶段 | 小矩阵证明低成本；本地模拟等于部署隐私或真实网络测速 |
| 多seed、更多划分及普适性 | 当前后置 | 诚实报告一个seed、两个起点的开发诊断 | 把两个起点、轮次、类别或样本当作独立训练seed |

每条证据不足的意见采用“承认可回答的边界→指出当前证据→给出对应实验或暂时收窄主张”的回应方式，不用“审稿人误解了”代替实验，也不许诺本轮补齐全部证据。

## 6. 文件可用性与实现前置

本地轻量A结果包有CSV、JSON、逐轮tokens.npz，但本次未找到SFRA模型的.pt/.pth文件。代码会保存事件状态、每轮commit.pt及滚动覆盖的sfra_last.pt；因此“代码会保存”不等于“本地已具备任意轮续训状态”。

- 日志分析现在即可执行。
- 候选前向需要基础模型、对应A事件的更新前/普通提案状态、正式提交状态及固定见证，先在服务器检查。commit.pt中的before_lora是普通提案，不是A更新前状态，不能拿错增量起点。
- 短程Full-CP分支还需完整历史状态、来源缓存、协议和可控随机状态。普通的--resume会强制恢复原配置，不能换一个method就冒充合法分支。需独立诊断入口或经过验证的状态重建。
- 第60、80轮都是五轮历史块边界，便于核对历史计数；若重建，仍须核验初始参照、历史有效位、缓存及原模型哈希。不能清空历史来简化恢复。
- 状态文件缺失时先列清单、回收服务器文件；不得默默从头跑多组长训练来填补准备成本。

## 7. 交付与停止位置

当前设计对应的交付物为：一张类别损害表、一张四候选同状态对照表、三条分支的两段五轮曲线、可用时的旧/新能力保留表，以及成本与状态核对表。μ=0的两次修正单独计费，不冒充续训分支；Flat探针本轮后置。

本轮完成后应能决定：A的分类代价主要在哪里；同等有效步幅下方向修正是否值得继续；是否有必要试一个分组CP候选。来源因果、新颖性、历史独立贡献、B作用和长期稳定性依旧按各自证据判断。
