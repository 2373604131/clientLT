# 方法B问题2：类别冲突与共享来源利用的实验设计

日期：2026-09-27。状态：实验协议；独立实现已完成CPU检查，尚未进行真实GPU验证或新的正式训练。正在运行的问题1三组实验保持原配置。

独立入口、四组目标与事件重放的命令见[运行说明](cliplora_b_problem2.md)。本文件记录实验设计依据与判定规则。

本文件将《方法B_类别冲突修正方案_20260927.md》的候选改法转为可检验的协议，不预设逐类反馈或损害惩罚一定有效。

## 1. 本轮究竟要回答什么

**相同来源、相同数据和相同优化预算下，现有共享C是否已经处理了类别间冲突；如果仍有明显损害，改变类别反馈的组织方式能否改善实际共同更新？**

分成三个可证伪的问题：

1. 来源层面：正收益筛选是否真正改变了共享来源库和输出更新？
2. 作用层面：原始donor的单独收益，与经过C重组后在共同更新中的作用是否一致？
3. 改法层面：类别权重和逐类损害反馈是否改善收益—代价关系，而非仅缩小更新？

候选池含全部donor，并不意味着C不能区分、变换和利用来源。反过来，新目标有效，也不能证明原来的donor筛选有效。这两类贡献必须分开归因。

## 2. 与问题1衔接：先冻结共同基线

问题1的三组为非尾类别轮换采样下的w=0.5/0.35/0.2。回收结果后，在启动问题2的比较前，统一锁定一个参考权重 `w_ref`；不为问题2各个候选方法分别挑选最有利的w，也不把单seed开发结果称为最优配置。若结果尚不足以支持选择，w=0.5可作为保持原组间系数的参照。

问题2所有对照固定：

- Full-CP方法A，lambda=10、mu=1；原本地训练、LA、样本量FedAvg和数据划分协议。
- 同一非尾类别轮换采样规则、接收端集合、Tail20定义、每步样本量及每次迁移时机。
- 每donor每模块的完整矩阵C，原始donor更新固定，C每次从0初始化。
- 同一个共享候选供所有接收端反馈，最终仅提交一次共享残差。
- 首轮比较保留Adam学习率0.3、两步、原C正则及其归一化。
- 同一校准清单与独立随机数流；机制重放使用完全相同的模型状态和原始donor更新。

单轮重放固定实际输入张量。完整训练的不同方法在第一次B更新之后必然形成不同模型和donor更新；完整实验只固定协议和随机调度，不能声称之后仍使用相同的donor张量。

## 3. 实验D0：来源筛选是否产生实际作用

### 已有证据与现在能做的工作

旧共享B运行的8次并集均含全部30个客户端。因此，这些事件的筛选并集与全集在成员上相同；记录每个接收端通过的关系数不等于全局排除了来源。

本次补算还比较了 `ordinary_global_B` 与 `transferred_global_B`，即同轮A更新之前的真实共同更新：

| 训练侧监测对象 | 轮次—接收端—类别记录 | LA改善 | LA受损 |
| --- | ---: | ---: | ---: |
| 尾类 | 584 | 486 | 98 |
| 非尾类 | 1776 | 1198 | 578 |

每轮监测20个尾类、65个非尾类；非尾并未覆盖全部80类。严格以损失变化的正负计数，另保留损害幅度，避免把微小数值波动与较大损害混为一谈。

这些是可能与校准重叠的训练侧重复测量，不是独立测试证据；也不能与54.9%的原始“donor—接收端”混合收益比例直接比较，因为统计单位和干预均不同。它们说明应继续调查最终共同更新，而非由原始冲突直接认定C无效。

### 待执行的同状态检查

在一个并集全覆盖的事件上，对比原并集与全集，保持donor顺序、校准清单、C初始化和优化设置一致。比较每步C、最终残差和模型输出的数值误差，而非只比较准确率。

若二者在复现精度内一致，确认该事件的筛选没有改变更新；耗时及通信统计可能不同。没有必要为一个等价实现先安排两次100轮训练。

问题1新运行仍需逐事件核对并集。若某事件不是全覆盖，不能直接复用“全集等价”的结论。后续新目标比较应统一来源规则，并补齐采用同一规则的基线。

## 4. 实验D1：原始有益关系能否代表C之后的实际作用

预先选第30、60、90轮，覆盖迁移的早、中、后期，避免按效果挑轮次。统一使用一个参考运行的这些状态；它们是局部机制比较，不代表候选方法自己的完整训练轨迹。

记录两种量，正数均表示有益：

1. 原始探测收益：`g_raw[k,c,j] = ell[k,c](B_bar) - ell[k,c](B_bar + 0.1 * deltaB_j)`。
2. 固定C和其他来源后的条件贡献：`g_used[k,c,j] = ell[k,c](B_bar + R - R_j) - ell[k,c](B_bar + R)`。

其中 `R_j = deltaB_j @ C_j / M`，M为完整来源池大小，各模块分别计算。移除来源j时只令该项为0，不改变分母、不重新训练C，也不重新筛选来源。

每个预选事件，对全部来源作一次这样的移除诊断，仅增加前向评估；无需为每个donor跑一条训练轨迹。主比较仅使用两种测量均存在的接收端—类别—donor记录。原始日志仅包含符合缺类条件的目标尾类；其他位置应标记未测量，不能填0或推断其收益。

报告原始正/负关系在重组后仍正/变负/转正的比例与幅度，同时保留每轮结果。条件贡献包含与其他来源的交互，不能相加当作对总收益的唯一分解，也不等于重新训练后这个donor的必要性。

原始探测的注入尺度与R_j通常不同，且第二种测量处在组合更新中。两者用于检验原始判断能否代表实际使用情境，不把绝对数值直接当成同尺度效果，也不能将符号变化单独归因于C的方向变换。

这个诊断若显示许多原始负收益来源在重组后有益，就反对简单收紧原始gain阈值。若原始收益能稳定对应后续作用，也只说明它可能有选择价值；是否需要独立筛选模块仍需控制实验。

### 重放所需材料

需要正常B事件保存的轮初LoRA、普通聚合后的LoRA、客户端原始B更新与顺序，基础模型及配置、数据划分、LA先验、校准和探测样本清单，以及共享C。普通B的bridge/event `state.pt`实现中包含原始更新，迁移 `commit.pt`保存提交前后状态；优先核对服务器现存文件，避免重复采集。

本地旧共享B分析包检索到8份donor分数、8份C矩阵和8份逐类指标，但没有 `.pt/.pth` 状态。单靠这些CSV和C矩阵不能执行上述反事实前向。先复用服务器原始状态；若缺失，之后在计划中的参考运行保存事件，不为了本方案修改或中断正在进行的三组实验。尚未执行的重放不能写成已经验证的结果。

## 5. 实验E：两个因素的最小机制比较

上一份建议的三组嵌套比较，可以判断改法逐步加入是否改善，却不能区分“损害项单独就足够”与“两项必须结合”。因此先在单事件重放做一个2×2比较；这不意味着立即启动四次100轮训练。

| 编号 | 类别反馈的汇总权重 | 逐类损害项 | 主要作用 |
| --- | --- | --- | --- |
| E00 | 原客户端分组均值 | 无 | 原目标基线 |
| E10 | 类别平均 | 无 | 单独检查类别权重 |
| E01 | 原客户端分组均值 | 有 | 单独检查损害反馈 |
| E11 | 类别平均 | 有 | 检查两项是否需要结合 |

另记录 `C=0` 的当次不迁移参照。它来自已经到达该事件的参考轨迹，不是全程A-only结果。

### 精确定义权重，避免重新混入问题1

每步在预先固定的校准批次上，计算每个接收端k、类别c的平均LA `ell[k,c](C)`。令 `a0[k,c]` 为原损失的实际样本系数汇总到类别后的权重：客户端等权，客户端内部按现有尾/非尾组系数和组内样本量分配；只有尾类的接收端继续遵循原规则。

先计算原目标在每组的实际总权重 `alpha_G = sum_(k,c in G) a0[k,c]`。类别平均版本使用：

`a1[k,c] = alpha_G / (number_of_observed_classes_in_G * number_of_observed_receivers_for_c)`。

也就是先同类跨接收端平均，再跨类别平均，但保持本步尾组与非尾组的总权重不变。不能直接用名义w替换alpha_G，否则遇到只有尾类的客户端时，可能把组间权重也一起改变。

这里改变的是组内类别和接收端之间的分配，正是待检验因素。权重依据采样清单生成，不依赖测试精度或损失大小；未覆盖类别没有可用反馈，不能假装纳入平均。

### 损害目标

固定当前批次在C=0时的损失并停止梯度：

`h[k,c](C) = max(0, ell[k,c](C) - stopgrad(ell[k,c](0)))`。

令v=0为原权重，v=1为类别平均权重；b=0为无损害项，b=1为有损害项：

`J[v,b](C) = sum(a_v * ell(C)) + b * beta * sum(a_v * h(C)) + lambda_C * Reg(C)`。

首轮机制比较预先固定beta=1、损害容差=0；beta=1只是同单位下的初始检验值，不是经过验证的最优超参数。C正则继续用原系数与归一化。逐类先取正部再平均，尾类与有反馈的非尾类都纳入。

原分类目标已经会权衡收益和损害；新增项相当于额外关注损失超过迁移前水平的单位。它允许取舍，不能保证逐类无损。

两步使用不同批次，必须分别缓存各自C=0的参照。标准ReLU在C=0时不会提供新的损害梯度；对于相同权重版本，有无损害项的第一步应一致，第二步才有机会不同。将此作为实现核验之一，而不是声称两步足以收敛。

### 比较哪些差值

- E10−E00：类别汇总的作用。
- E01−E00：在现有权重下，损害反馈的作用。
- E11−E10：类别汇总之后，损害反馈是否仍有价值。
- E11−E01：加入损害反馈之后，类别汇总是否仍有价值。

同状态重放只隔离当次更新。预选3个事件、4个配置、每次2步，共24个共享优化步骤；每步仍包含所有反馈端的计算，不是24个本地mini-batch。额外诊断前向及实际耗时另计。

## 6. 统一评价口径与判定规则

### 单事件：同时看收益和损害

对所有配置使用同一套评价权重与同一组监测样本，不能让每种方法按自己的目标权重评价自己。

固定定义 `gain[k,c] = ell[k,c](C=0) - ell[k,c](C_final)`，分别报告尾与非尾的：

- 类别宏平均净收益。
- 正收益量 `mean_class(max(gain,0))` 与损害量 `mean_class(max(-gain,0))`，先在同一类别内平均接收端，再平均类别；净收益等于二者之差。
- 改善/受损单位比例、每类跨接收端平均后的改善/受损类别数，以及最大损害幅度。
- 实际LoRA残差范数及其与普通更新的比值，不能仅比较C参数范数。
- 固定同一套两批校准数据上的C=0、第一步后、第二步后逐类损失与目标轨迹。

报告校准数据上的优化效果与未参与C拟合的样本上的诊断是否分离。现有probe允许与校准重叠，不能将它称为独立验证集。若训练样本余量允许，另固定一份不参与优化的诊断清单，各配置共用，并记录实际重叠及覆盖；不因要求留出而抽空稀少尾类。

三次事件各自报告，也作轮次等权汇总。轮次、客户端或类别不能当作独立seed来计算方法显著性。

### 按结果决定是否进入完整训练

| 观察 | 允许的判断与下一步 |
| --- | --- |
| E00已具有较好的收益—损害取舍，其他配置无一致优势 | 优先简化冗余筛选，停止追加这两项机制 |
| E10改善取舍，E11无额外收益 | 只保留类别权重候选，不增加损害项 |
| E01有效，E11无额外收益 | 优先验证仅增加损害反馈的较简方案 |
| E11优于单项版本 | 保留组合候选，并在完整训练保留必要单项消融 |
| 损害减少，但正收益和残差范数也明显下降 | 先做残差幅度匹配诊断，不能直接归因于类别信息 |
| 校准损失改善，但可用的独立诊断或完整训练不改善 | 不宣称获得泛化收益，检查反馈代表性或停止此路线 |
| 所有目标的优化轨迹都明显不稳定 | 先对所有相关对照采用相同的学习率/步数修正，再比较目标；不能只给新方案更多预算 |

这里的“改善取舍”优先指保留相近正收益时降低损害，或相近损害时提高收益。如果只是不同取舍点，完整报告，不用临时改综合分数选赢家。小样本事件诊断只用于筛除明显无效实现和决定验证顺序，不足以定稿方法。

### 条件控制：是否仅仅缩小更新

若候选残差较小，对E00残差作整体缩放，使其有效LoRA范数匹配候选，再评价同一固定监测集；不使用测试结果选择缩放系数。零范数单独处理，不能除零。

这是条件诊断对照，不是把方法改为标量donor加权。如果幅度匹配后原版同样好，证据支持规模控制，而非新目标改善了更新方向；若仍有差异，再用完整训练验证。

## 7. 正式100轮训练只保留必要组

问题1结果回收并固定w_ref之后，先在seed42完成开发比较。只有在来源规则、采样、预算、实现和诊断开销均可对齐时，才能复用对应的现有基线；若有不一致，明确补一组可比基线。

- 基线E00必需。
- 先跑机制诊断最有依据的候选；若结果不稳定或是明确取舍，再检查一个必要的相邻对照。
- 如果最终希望同时主张“类别权重”和“损害反馈”两个贡献，正式实验必须保留E10、E01和E11的必要消融；不能只凭单轮2×2结果证明两者都必要。
- 固定最终配置后，用至少两个预先确定的新随机种子做与E00的配对确认；seed42作为已用于开发的结果单列，不能把多次开发选择忽略掉。数据协议、客户端调度和种子相关划分需逐组核对。

完整训练报告每seed的81—100轮平均Overall、Tail20、Few30和Medium35等分组，再汇总配对差值和跨seed波动；这些类别组存在重叠，不能相加。第100轮值作为辅助，不能替代预定主口径。

完整训练还检查八次迁移的即时收益、同轮A之后的变化与后续保持，以及额外计算/通信。正式效果不能由当次LA改善或C参数范数推断。

完整方法应从共同初始化按各自规则运行；若复用第一次B介入前的共同前缀，需要保存并核验模型、历史、优化器及随机状态且实现明确支持。不能将改变配置后从中后期checkpoint继续跑称为从头的公平主结果；现有resume还会核对配置一致性。
