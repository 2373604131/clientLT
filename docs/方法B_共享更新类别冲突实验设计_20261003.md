# 方法 B：共享更新的客户端内类别冲突实验设计

日期：2026-10-03。E1/E2及关闭保护的校验入口现已实现，CPU测试通过；尚未启动服务器GPU实验。启动、恢复与打包见[运行说明](cliplora_b_class_guard.md)。后续条件性对照仍为设计，不自动启动。本稿调整了前一稿的执行顺序，不要求两套实验同时运行。

## 1. 本轮只回答一个问题

当多个类别共用最终共享更新时，按客户端/分组平均评价会不会掩盖部分类别的损害？如果将这种损害明确反馈给 C，能否改善最终尾类测试精度，同时控制额外副作用？

每个 C 对应 donor 与 LoRA 模块，不是接收客户端独享的模型。所有 donor 的变换更新最终叠加到一个共享模型，因此不能假设按类别反馈就能隔离类别作用。本轮不增加类别专属 C、推理分支或教师。

本轮验证损害控制是否值得保留；不能单独验证 donor 筛选有效，也不预设冲突就是 B 测试收益小的根因。

## 3. 第一轮两组新增完整训练

| 组别 | 额外保护规则 | 用途 |
|---|---|---|
| E0：旧共享B | 无 | 已有参照 |
| E1：客户端分组平均保护 | 在每个客户端内，分别保护尾组、非尾组的平均损失 | 检验一般性的保守约束 |
| E2：客户端—类别保护 | 在每个客户端内，对每个观测类别先判断损害，再汇总 | 检验平均值掩盖类别损害的问题 |

固定A、原Tail20、数据与客户端分配、22个反馈端、轮换采样、w=0.35、每donor独立C、基础LA和C正则。保持rank4、6模块、迁移轮次30/40/50/60/70/80/90/100、每次两步Adam、lr=0.3、C正则0.001、固定第二步提交。沿用来源候选生成规则；不增加S、不更改Top-K、不缩窄成3个目标客户端。

匹配每个事件/步骤的实际采样身份、变换和优化步数，不仅匹配batch size。训练轨迹改变后，来源探测分数可不同。新增参照前向、诊断和通信计算单独计数；不声称全过程计算完全一样。

## 4. 两个保护规则的精确定义

theta0为本次B注入前的实际普通聚合模型，R(C)为最终共享残差。接收端k当前批次中的类别c有n_kc个样本，定义：

`d_kc(C) = mean_{x in batch(k,c)} LA(x; theta0+R(C)) - mean_{x in batch(k,c)} LA(x; theta0)`。

两项必须使用同一批图像和同一变换；theta0结果停止梯度。不能用上一个批次或历史损失替代当前参照。

令g为尾组或非尾组，r_kc=n_kc/sum_{c in g}n_kc，w_kg沿用原本该客户端的组权重。当前实验所有反馈端有两组，分别0.35/0.65；若出现单组，沿用原损失的单组权重1。

客户端分组平均保护：

`H_client(C) = (1/K) sum_k sum_g w_kg * relu(sum_{c in g} r_kc d_kc(C))`。

客户端—类别保护：

`H_cell(C) = (1/K) sum_k sum_g w_kg * sum_{c in g} r_kc relu(d_kc(C))`。

二者只改变“先平均再截断负收益”还是“先按类别判断损害再平均”。保留原样本权重，不把只有一张图片的类别单元直接赋予与大单元相同总权重。未观测类别不虚构反馈。尾组与非尾组都检查；E1允许各组内部类别相互抵消，E2阻止损害在这一步被改善类别抵消。

例如同一客户端、同一组中两个等样本量类别，d分别为-0.10和+0.08，E1额外惩罚为0，E2为0.04，再乘客户端和组权重。最终仍只有一个共享C组合，未将两个类别分开更新或分开推理。

两组均使用：`L = 原基础混合LA + 0.001*原C正则 + 1.0*H`。

保护系数1.0为固定首轮开发值，不做网格搜索，也不把它说成最优。两种H本来就可能有不同幅度；凸性给出H_cell >= H_client，因此E2胜出仍不能直接排除只是正则更强，需要后续幅度诊断。

这不是给错误类别加新标签或迁移教师，而是约束本次共享更新的局部副作用。各客户端可本地计算惩罚并按现有协议返回C梯度，无需把原始图像集中到服务器。

### 两步优化下的边界

C从0开始，第一步时H的值与标准ReLU梯度都为0。因此E1/E2主要在第二步响应第一步引起的损害。需保存第一步后的激活与第二步保护梯度；保护未介入时，不能把失败归因于C容量不足。第二步仍可能产生新损害，本设计不保证训练损失逐类不升，更不保证测试精度不降。不额外追加修正步或根据测试结果回退。

### 主要效果

- 固定Tail20，第81—100轮正式提交模型的测试ACC均值。
- 同窗口Overall、Head20、Middle60、Non-tail80，及相对A/旧B/E1的配对差。

- 不根据Tail30或偶然最佳轮重新挑主指标。

### 自动记录的解释量

- 实际注入前后，在固定训练监测样本上按客户端—类别记录LA、ACC及样本数。
- H的激活比例、损害量及梯度相对基础梯度的大小。训练与诊断范围分别标注。
- C范数、有效残差范数、相对普通聚合更新的比例。
- 算法与诊断前后向图像数、同步量、通信估计、耗时。

只用已有训练流程自动记录，不新建手工逐轮重放任务。训练侧损害减少必须结合最终测试收益判断；原来准确率未下降的置信度变化，也可能被过度保护。

## 6. 结果如何决定方法修改

| 结果 | 解释边界 | 修改方向 |
|---|---|---|
| E2优于E1和E0，尾类提高且副作用减少 | 支持细分损害反馈有实用价值；还需排除幅度因素 | 保留客户端—类别反馈，继续共享C，不改成每类一个C |
| E1/E2近似，二者均优于E0 | 一般保护可能足够，没有证明细粒度必要 | 优先保留简单E1，不增加逐类复杂度 |
| E2减少训练损害，但测试Tail20不提高 | 更保守或保护了训练噪声，不等于增强学习 | 不以损害计数作为成功标准，不直接定稿 |
| E2训练损害和尾类效果均无改善 | 可能干预弱、样本噪声或当前更新形式不合适 | 先检查激活和梯度；不能直接判定C表达能力不足 |
| 保护导致尾类退步，即使Overall提高 | 当前约束与预定尾类增强职责不合 | 不把Overall临时升为成功主指标；本配置不采纳 |
| E1/E2都不优于旧B，且保护实际生效 | 本轮不支持新增保护模块 | 保留旧B，停止该分支；不等于否定所有来源利用方法 |

## 7. 有收益才追加对照

### 7.1 匹配幅度：判断细粒度收益是否只是缩小更新

若E2胜出，运行E1但在每一步匹配E2已完成训练提供的有效残差范数。匹配的是LoRA实际有效更新范数，不是C范数。范数参照只来自训练，不读测试指标。若E1本身胜出、只想验证保护是否超出幅度控制，则对E0做相应匹配。

来源C、正则和优化设置不变；每次投影按统一规则处理C与Adam状态并记录，实现时必须明确。参考方式可沿用当前诊断投影约定：在Adam步后统一缩放C，保留Adam动量状态，不因比例缩放偷偷重置优化器。参考为零时残差置零；零残差无法匹配正范数时显式报错，不能跳过并仍标记匹配成功。

该对照依赖候选的训练范数轨迹，不是独立部署算法。后续模型状态不同，不能称所有事件都同状态比较。

若匹配后性能与候选相当，则优先简化为更新幅度控制；如果候选仍更好，才支持其价值超出简单步幅变化，但不唯一确定所有潜在机制。

### 7.2 匹配直接校准：检验保留donor C的价值

对最终选中的E1或E2，以相同反馈数据、基础损失、保护项、两步预算和候选自身的有效范数轨迹，构造直接残差校准。旧校准结果不能代替新增保护后的匹配对照。

若直接校准仍不差，不能声称donor C带来额外尾类精度价值。该比较改变参数化和正则，不能进一步唯一归因于C子空间不足；成本和非尾取舍另行如实报告。

### 7.3 来源反馈：另一个问题，条件性后续

只有继续研究“来源对应是否提供额外支持”时，才在选定的共同保护规则上比较正确来源反馈与匹配的打乱反馈。旧稿S可作为候选，但不是当前两组实验的默认组成。

正确反馈与打乱反馈必须保持来源资格、系数分布、反馈样本和参数量一致；正确关系若没有优势，不能保留筛选有效的机制主张。保护成功本身不等于筛选成功，保护失败也不证明来源反馈一定无用。

## 8. 执行顺序与固定标准

1. 先新增E1、E2各一个seed42完整训练；停止旧稿S/H三组同时启动的安排。
2. 若两组都无实用收益且干预生效，停止本轮保护分支；不无条件运行本稿所有后续对照。
3. 若有收益，选择一个候选，补支持其具体主张的幅度/直接校准对照。只需更简单的保护时，不强行保留细粒度模块。
4. 候选通过后锁定配置，在用户指定的0、3407做配对复核；保留所需关键对照，旧基线在协议一致时复用。seed42为开发，3407旧结果已看过，不称完全未见的保留测试。

沿用前稿的建议实用门槛：相对旧B，Tail20提升至少0.10个百分点，Overall下降不超过0.05个百分点，且相对A仍有正向尾类增量，才进入进一步确认。这是拟在新结果产生前固定的工程标准，不是显著性检验或普适论文标准。

最终建议0、3407的尾类配对增益都为正，平均达到实用门槛，Overall各自满足约束，同时核心机制对照方向一致。若只是某个种子改善，则报告不稳定而非继续按测试调参直到成功。轮次、类别和客户端事件不能增加独立种子数。

本轮已新增独立实现与运行入口，冻结的旧训练文件和原始实验结果未修改。所有候选的真实GPU运行及精度效果待服务器实验验证。
