**T01：先固定比较口径，建立可信的同频基线**

怎么做：

- 以 `s` 对比 `full-cp`。保持相同训练样本、划分、初始化、客户端顺序、LA、A/B 优化器、A 第 1–90 轮更新、B 第 1–100 轮更新。E3 保留为周期刷新参照。
- 保存训练种子与划分种子，区分“同划分换初始化”和“重新生成划分”。同一个种子组合下，各方法使用同一套协议文件和见证清单。
- 沿用当前主终点：第 81–100 轮正式模型的 Overall/Head20/Middle60/Tail20 均值；另报第 90、100 轮和 91–100 轮变化，解释停止 A 修正后的表现。不能选择各方法最好的测试轮次。
- 核心对照先做一个开发种子的短程正确性检查，再做完整 100 轮；确认实验定义正确后，补到至少 3 个配对种子。报告逐种子差值和不确定性，种子少时不要声称结论精确。
- 机制对照优先使用固定全局类频、固定每客户端样本量的匹配划分；已有标准 Dirichlet 保留作另一组鲁棒性证据。匹配要核对原始样本集合、每类总数、每客户端容量及日程，不只核对划分名字。
- 同一规则用于两个拓扑，先固定超参数。旧 seed42 已参与开发，应标成开发结果；新增确认结果避免按测试指标选参数。

验收：先给出“协议相同项、唯一变化项、预算不同项”三列清单，再出结果表。若 Full-CP 对 S 没有稳定收益，先查 CP、目标尺度和优化；此时不急于增加来源机制复杂度。若只有尾类改善、整体下降，应报告权衡。

**T02：检验低有效来源数能否预测后续功能下降**

这项任务回答老师最核心的逻辑缺口。高集中度不能从公式直接推出高遗忘风险。

建议以同频普通基线 S 的轨迹为主要观察对象。给 S 增加只读见证诊断，计算来源，但不把诊断用于训练、历史目标或选择模型；诊断必须隔离训练随机数并单独计成本。只分析 Full-CP 的最终下降会受到保护干预影响：本来更容易下降的单位可能恰好被保护得更多。

每个 `(seed, round, client, class)` 记录：

- 本地类样本数、全局类样本数、所属客户端样本量、类别持有客户端数。
- 两视图 margin、正向来源数量、`n_eff`、当前 `rho`、有无当前支持。
- 各视图加权正响应 `P_qv=Σ_j p_j[r_qvj]_+`、负响应 `N_qv=Σ_j p_j[-r_qvj]_+`、净响应 `P_qv−N_qv`；同时保留未加权总量和当前阈值下的保守正响应统计。
- 来源优先级缓存是否被复用、距离上次有支持的轮数。无支持时的 `n_eff=0` 是存储值，不能解释成“无限集中”；该组单独分析。

建议分开三个结果，避免把不同现象都叫遗忘：

1. 同轮 A 普通聚合变化：`F_proposal(t)−F_post_B(t)`，用来检查一阶预测与真实前向是否一致。
2. 下一轮 B 阶段变化：`F_post_B(t+1)−F_committed(t)`，说明已提交能力是否在随后 B 训练中下降。
3. 从第 t 轮提交到 t+h 轮提交的变化，预先固定 `h=1、5`。控制起点 margin；如果预测终点变化，还应做控制测量时 margin 的敏感性分析。

分析步骤：

- 先画按集中度分组的下降概率和下降幅度，不用它直接作因果结论。
- 在样本量、起点 margin、正负响应总量、轮次和拓扑相近的单位间比较。用不包含集中度的预测模型，对比加入集中度的模型；训练和验证按种子/连续轮次块分开，不能随机打散重复的单位记录。
- 以独立运行作为主要重复单位；不能将几万个相关的“单位×轮次”当作几万个独立实验。样本不足时只报告探索性关系。
- 报告一阶净响应与实际 A 变化的符号一致率和误差；若近似失真严重，先查量级、margin 的竞争类别切换和视图稳定性。

验收：明确结论属于“独立预测信息”“仅相关但解释不清”或“未发现新增信息”。即使预测失败，T03 仍可能证明它是有用的优化权重，但论文应放弃“低有效来源数必然更易遗忘”的解释。

如果主要问题确实来自忽略实际聚合权重，可先比较诊断候选 `rho_p=Σ_j(p_j a_qj / Σ_i p_i a_qi)^2`，分母为零的单位仍单独处理。它测量的是实际聚合权重下的正向集中度，语义与原指标不同；先检验新增信息及消融收益，再决定是否替换原 rho。不要一开始就把集中度、负响应和稳定性拼成多个新组件。

**T03：用单因素消融判断来源权重是否必要**

应在同一个 Full-CP 实现上拆出独立开关：`weight_mode`、`use_history`、`classification_weight`、`gain_mode`。这些是建议增加的接口，目前不是可直接运行的命令。

| 实验组 | 唯一改变 | 能回答什么 |
|---|---|---|
| Full-CP | 无 | 新版主方法 |
| Uniform-CP | 有效单位的原始 rho 全设为 1，再全局归一化 | 集中度加权是否有价值 |
| Shuffle-CP | 在匹配条件内打乱单位与 rho 的对应 | 是否依赖正确的来源信息，而非权重不均本身 |
| PositiveCount-CP | 用 `1/正向来源数量` 替代 `1/N_eff` | 响应幅度的集中程度是否比简单功能支持数更有用 |
| ClassCount-CP | 用 `1/持有类别c的客户端数` 替代 rho | 动态功能来源测量是否超越静态数据支持先验 |
| NoHistory-CP | 仅禁用历史目标 | 历史的独立价值；用于 T06 |
| Full（无 CP） | 仅令 CP 强度为 0 | CP 的独立价值；用于 T07 |

关键细节：

- Uniform/Shuffled/Count 均保持当前目标、历史规则、激活规则、CP、三步更新和归一化规则。算法规则相同不代表长期运行后的目标数值仍相同，模型轨迹分叉后允许自然演化。
- Shuffle 必须打乱功能单位与 rho 的对应，不能只打乱来源客户端编号。按本地样本量、当前 margin、支持/历史状态等预先确定分层；报告可交换单位比例，过小分层合并规则先确定。
- 对缓存来源权重，固定缓存何时更新及无支持如何处理。把“当前有支持”和“仅历史激活”分层，避免打乱顺便改变缓存语义。
- 计数为零时不要取倒数；对动态正向计数保留与原方法相同的缓存时点、初始值和激活规则。
- 采用独立的打乱随机数流，不改变训练增强、客户端次序等随机性。离线可做多次打乱看波动；训练比较需完整重跑，不能只对旧结果换标签。

验收：输出配对差值以及 Tail/Overall/功能下降的共同变化。Full-CP 若优于简单和打乱对照，才有证据强调来源信息；若相当且不确定性足够小，选更简单的方案。差异不显著本身不等于等效，需要结合置信区间与预先约定的实际意义阈值。

**T04：拆开来源权重、少数改善增强和额外见证训练**

当前目标是 `T_cur=min(2,F0+0.5u)`，`u` 是正向来源的未加权平均。它包含增强作用，不能统一解释成保留原 FedAvg 已有改善。

先做不改算法的诊断：同时记录 `0.5u`、`Σp_j a_qj`、加权净响应和真实普通提案改善；在普通提案改善接近零或为负时单独分组，避免比值失真。报告修正比值、普通更新绝对范数、修正绝对范数及与半径的比例。

然后做一个小型 2×2：

| 权重 | 当前未加权目标 `F0+0.5u` | 聚合权重尺度目标 `F0+0.5Σp_j a_qj` |
|---|---|---|
| 来源 rho | 原目标组 | 较弱目标组 |
| 统一 rho | 去掉集中度优先级 | 两项都简化 |

两列都保留 margin 上界和相同 CP。第二列是诊断替代方案，不预设它更好，也不把它称作有保证的纯保持。为避免历史 `max` 掩盖当前目标差异，可先在四格都关闭历史，或做同起点单轮分支；之后再确认结论能否迁移回完整方法。

另外补 S + 额外见证 LA 训练：从普通 A 提案出发，固定 B，使用同一见证和视图做普通分类训练；见证类/客户端加权口径明确。按测得的前后向量或 FLOPs 匹配额外计算，并报告实际时间差；“都是三步”不足以叫同预算。新对照的优化器和学习率先固定或用同等验证预算选择。

验收：如果统一权重下的增强目标已取得几乎全部收益，贡献应转向功能增强。如果等预算见证训练已复现收益，需要重新证明来源测量的必要性。如果来源权重在相同目标下仍稳定更好，才支持其独立价值。

**T05：判断是否只是隐式类别重加权**

每轮汇总 `W_c=Σ_{q:class(q)=c}ω_q`，画它与类频率、持有该类的客户端数及该类收益的关系。只看相关性不够，增加一个保留类别总权重的对照：

`ω_uniform-within-class(k,c)=W_c / 当前该类的有效单位数`。

这个对照保留本轮每类分配到的总权重，把类内客户端—类别差异抹平；目标、CP、激活集合保持相同规则。无有效单位的类别不参与除法。也可在类内打乱权重，保留类内权重分布。

严格的一步归因应从共同检查点分支，固定同一 `W_c`、目标、半径和优化起点。独立完整运行时，每组从自己的模型重新计算 `W_c`，它只能支持策略层面的比较，不能称作全程数值相同。

验收：若来源权重优于保留 `W_c` 的类内均匀对照，才支持客户端—类别层面的额外价值。如果静态类频重加权也能达到相近表现，应优先考虑简化。

**T06：拆开 B 阶段下降、A 聚合下降与历史修复**

对同一见证、同一视图定义四个分数：

- `F_prev`：上一轮正式提交模型。
- `F_B`：本轮 B 训练聚合后。
- `F_ord`：本轮普通 A 聚合后。
- `F_commit`：本轮 A 修正提交后。

分别计算 `ΔB=F_B−F_prev`、`ΔA=F_ord−F_B`、`Δcorr=F_commit−F_ord`。同一分数定义下三者相加等于本轮总变化，是精确的顺序记账；它不能单独证明修复的因果来源。第 2 轮起通常可由上一轮 `F_committed` 与本轮日志拼接；第 1 轮的初始逐单位分数需核对是否保存，缺失时补记录或重算。

历史审查记录：

- 有效历史单位比例、历史目标年龄、负 margin 的历史比例。
- `历史有效 & [H_q−F_commit]_+` 的幅度、连续违约轮数；无历史单位必须用 mask 排除。
- 仅历史激活的单位比例，以及历史目标高于当前目标的单位比例。
- 在目标由 `max(current,history)` 构成时，把梯度按“哪一目标支配该单位/视图”划组再汇总，报告各组梯度范数和夹角。不能把两个完整损失的梯度简单相加，冒充现有 max 目标的真实分解；范数占比也不等于因果贡献。
- Full-CP 对比 NoHistory-CP 的后期准确率、历史缺口和 CP 代价。

若历史缺口长期存在：在预先选定的早/中/晚检查点上，固定 B、rank 和半径，离线增加优化步数检查是否只是三步不够。找到更低缺口说明原优化不足；仍未达到目标也不能证明数学上不可行。

修改决策：先排查优化、尺度和陈旧目标。如果陈旧历史持续产生代价且无历史对照更好，再分别试滑动窗口或衰减历史中的一种。不要同时叠加两种机制。若主要补偿 B 引起的下降，定位为“A 阶段修复整个模型的功能回落”。

**T07：把 CP 当作软正则，测量它实际减少了多少损害**

直接利用新版日志，按正式第三步提交状态计算：

- `C_commit−C_ord`，报告上升轮次比例、均值、P90、最大值；数值容差要固定并做敏感性核对。
- CP 激活轮次比例，以及第 2、3 次梯度评估的激活比例。第 1 次从普通提案出发，梯度应为零，不把它混进频率解释。
- 原始和归一化功能缺口、目标满足单位比例、Overall/Head/Tail 变化。
- 功能梯度与分类梯度范数、夹角及是否存在剧烈来回修正。

对照必须是 Full 与 Full-CP；如已有代码，也可在同一 full-cp 路径令 `mu=0` 做一致性检查。中间第三次梯度评估对应更新前状态，不能代替更新后的最终损失；当前代码已额外评估正式提交状态。

验收不要求零违反，而是判断 CP 是否降低实际分类代价，是否保留有用的功能收益。若仍严重损害分类，先在开发/验证协议下分别检查 `mu` 或步长，不同时改变全部参数。保留固定第三步提交，除非后续明确把提交规则也作为方法修改并重新比较。

**T08：验证见证优化能否推广到未参与反馈的数据**

建立三种清楚区分的数据视角：

| 样本集合 | 是否正常训练 | 是否用于来源/历史/修正/CP | 可以回答的问题 |
|---|---|---|---|
| 见证 W | 是 | 是 | 训练目标是否被实现 |
| 反馈外训练样本 U | 是 | 否 | 收益是否仅局限于反复反馈的样本 |
| 独立验证/测试样本 | 否 | 否 | 是否有训练之外的泛化 |

在样本足够的单位上，用见证之外的本地训练图片建立固定 U，并确保它不参与四种反馈。它仍是训练数据，不能称作独立测试集。样本极少的单位可能不存在 U，报告可评估单位/样本覆盖率，不通过删除它们制造更漂亮的结果。

记录 W/U 上普通提案到修正后的 margin、普通分类损失和准确率；独立测试按类别和预先定义的来源组汇总。平均 margin 上升不代表准确率提高，因此两者都要报。

若另划本地验证集，应在所有比较方法训练前一致划出，并更新训练先验与协议；不要只给某个方法少用数据。测试集只作固定评估，不参与超参数选择、历史登记或提前停止。

验收：判断收益是否同时出现在 U 与独立测试，尤其检查少样本单位。若只改善 W，优先试训练侧见证轮换/增加独立反馈覆盖；轮换会改变历史分数的可比性，需保留独立固定历史评估集合或另行设计历史规则，不能直接轮换后沿用原历史解释。

**T09：完整核算训练、通信与同步成本**

当前 QR 基有 `d_A×m` 个 FP32 元素。此配置 `d_A=6×4×768=18432`，`m=30` 时一份为 2.109375 MiB，发给 30 个客户端为 63.28125 MiB/轮；全网下行口径与单客户端接收量分开报告。

建立一张分项表，包含：

- 正常 B 训练、本地 A 训练与各自上下行。
- 服务器 QR、基广播、来源坐标上传、响应返回和全局权重归一化。
- 三次候选下发、功能梯度上传、CP 分类损失及完整梯度上传。
- 最终正式模型下发、正式损失/历史分数反馈，以及评估与纯离线诊断。
- 每轮同步依赖阶段数，明确哪些可以合并；不要用 CSV 行数当网络往返数。

联合读取 `budget.csv`、`event_manifest.csv`、`sfra_costs.csv`、`evaluation_budget.csv`。训练事件总耗时与其内部计时若嵌套，不能重复相加；总时间用墙钟日志核对。分类前向复用了功能前向，不能把其计数再次加到总前向。

`sfra_costs.csv` 的 bytes 是代码按张量大小写出的模型估算。核对协议必须传输的标量是否漏计，并区分广播假设、逐客户端总量和实际运行环境。GPU 时间需同步边界或 CUDA events 核验；顺序模拟耗时不代表真实并行联邦网络耗时。

若收益成本不理想，先确认 T02/T03 的主机制，再一次只试一项降本，例如减少来源测量频率。频率降低会引入来源缓存陈旧问题，应同时检查；压缩/截断 QR 会改变响应估计，也需重新验证，不能视为无损替换。

验收：给出“相对同频 S 的增量计算与通信”及准确率收益，不单独用低 rank 或短坐标证明轻量。

**T10：根据证据重写方法定位与复现说明**

当前适合定位为 Technique Paper 中的 A 阶段模块。建议暂用：

> 在交替 LoRA 训练中，依据客户端—类别功能的正向来源分布分配修正权重，联合优化当前改善目标与持续历史水平，并对见证分类损失上升施加软惩罚。

这句话描述算法行为，不预设效果已被证明。T02/T03 完成后，再决定是否把“集中来源功能更易损失、因此应优先维护”升级为证据支持的解释。

必须调整的说法：

- “贡献保持”补充“当前目标可能增强少数来源改善”。
- “分类不下降保证”改为“对分类损失上升施加软惩罚”，列实际违反情况。
- “已正确掌握能力”改为“持续达到的改善水平”，因为历史 margin 可为负。
- “A 天然负责客户端支持”改为“在共同 B 固定的 A 阶段实施”；若要保留 A 独有必要性的主张，再增加参数块对照。
- 报告无当前正向来源且无有效历史的单位比例及表现；它们不受功能项保护。
- 写清 `scaling=alpha/sqrt(rank)=1/sqrt(4)=0.5`，代码位于 `utils/loralib/layers.py`，并非 `alpha/rank`。
- 保留“单一固定 rank 共享模型”的部署事实，把训练额外成本另列。

相关工作边界也应围绕机制联系：客户端贡献估计并用于聚合已有 [FedCE](https://arxiv.org/abs/2303.16520)，用记忆修正更新、缓解遗忘已有 [GradMA](https://arxiv.org/abs/2302.14307)。因此候选贡献应落在具体功能单位、正向来源集中度及目标维护之间的联系，而非这些概念本身。本次核查这些论文摘要用于确认该边界，不能替代完整新颖性检索。

**三、分阶段执行，避免一次跑完所有组合**

| 阶段 | 具体行动 | 进入下一阶段的条件 |
|---|---|---|
| A：复用数据 | 整理旧五组的修正比、历史缺口、阶段变化、权重和载荷；确认新版 CP 结果是否已有归档 | 形成数据缺失清单，避免重复训练 |
| B：补齐入口与诊断 | 独立开关、S 只读诊断、反馈外样本、固定边际诊断入口、配置与协议核对 | 短程运行确认没有多因素混淆，评估不消耗训练随机数 |
| C：核心开发实验 | S、Full-CP、Uniform-CP、Shuffle-CP，先同一个开发协议跑完整训练；成本同时记录 | 能解释结果、排除代码或协议错误，不要求结果符合预期 |
| D：确认与排除替代解释 | 核心比较补新种子及两种拓扑；追加计数、无历史、无 CP、等预算见证训练和类内均匀权重 | 明确来源机制的独立价值和适用边界 |
| E：有依据的修改 | 只改诊断指出的一处：目标尺度、历史、见证或成本；保留修改前结果 | 新版本在预定指标上有可解释改善，否则回到更简洁版本 |

核心四组 × 两拓扑 × 三种子为 24 次完整运行，是核心确认清单的规模，不含后续 P1 对照。不能把旧标准 Dirichlet 或无 CP 的 Flat 当成其中一格。已有运行只有配置、协议、记录完整相同时才可复用。各 P1 对照分批追加，不先对所有超参数做笛卡尔积搜索。

**四、如何根据结果修改方法 A**

| 观察到的证据 | 建议决定 |
|---|---|
| Full-CP 稳定优于 S，真实来源权重优于统一/打乱/简单先验 | 保留来源集中度作为主要候选创新 |
| 来源权重有效，但不能预测未来下降 | 改为“有用的修正优先级”，降低遗忘风险机制的主张 |
| 统一权重或简单计数在足够精度下表现相当 | 简化加权；重新评估完整来源测量是否仍是构造当前目标所必需，不能直接假定它可以删除 |
| 类内均匀权重保留几乎全部收益 | 把类别重加权视为主要解释，收缩客户端—类别来源创新主张 |
| 等预算见证分类训练复现主要收益 | 将额外训练作为强基线，重新审视机制必要性 |
| 历史长期主导缺口和冲突，无历史版本更好 | 查优化和陈旧程度后，尝试一种更保守历史规则或移除历史 |
| 见证改善，反馈外样本与独立测试不改善 | 优先处理过度适配，不能只加强见证损失 |
| CP 降低分类代价但完全抹去功能收益 | 检查目标增强幅度与优化权衡，不仅增大 CP 系数 |
| 来源机制有稳定独立收益，但成本高 | 再做来源测量频率或通信压缩的单因素降本 |

**五、逻辑骨架检查（tech-paper-template）**

| 思考环节 | 当前可成立的表述 |
|---|---|
| 背景 | Client-LT 下共享低秩模型需要兼顾不同本地类别功能；本地旧结果显示密集 A 适配与功能修正存在 Tail/Overall 权衡 |
| 局限 1 | 普通按样本量聚合不显式识别每个客户端—类别功能的正向支持分布；这不等于已证明集中功能更容易下降 |

| 模块 1 → 挑战 1 | 共同 B/共同 A 起点的来源响应与集中度测量；T02/T03 验证其价值 |
| 模块 2 → 挑战 2 | 当前/历史目标及三步联合修正，CP 作为该目标的配套正则；T04/T06/T07/T08 验证 |
| 候选贡献 1 | 方法节：客户端—类别来源感知的 A 修正机制 |
| 候选贡献 2 | 机制实验节：来源信息相对计数、类别权重及额外训练的独立价值，待验证 |
| 候选贡献 3 | 实验节：跨划分和种子的功能/分类收益及成本边界，待验证 |

四项检查：局限→核心想法、核心想法→挑战、挑战→模块在设计上对应；模块→已证实贡献目前尚未通过。按技能口径，证据不足却宣称贡献成立属于 CRITICAL 缺口。因此这是“待实验验证的骨架”，不应直接生成宣称有效性的论文 Introduction。
